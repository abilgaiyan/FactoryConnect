# FC-030.2C.1 — Concurrency Semantics Amendment and Re-Freeze

## Status

**CLOSED / FROZEN — NARROW CONCURRENCY SEMANTICS AMENDMENT AUTHORITY.**

This document narrowly reopens, amends, and re-closes FC-030.2C.1 after the FC-030.2C.3 real-SQL locking investigation.

It does **not** reopen migration 005, alter the frozen lock-acquisition order, weaken writer isolation, authorize application locks, authorize a database-wide publication mutex, or authorize projection/manifest/evidence DML before the frozen lock boundary is satisfied.

It supersedes only the prior interpretation that "distinct processors remain logically independent" requires zero transient SQL Server lock blocking between distinct processor publications.

All other FC-030.2C.1 authority remains frozen, including the replacement closure in:

```text
docs/features/FC-030.2C.1-contract-correction-and-replacement-closure.md
```

The DML authorization boundary is frozen as:

> **Projection/manifest/evidence DML is authorized only after the implementation has acquired and validated all required projection, manifest, and evidence locks in the frozen order within the same transaction.**

No projection, manifest, or evidence DML may occur before that boundary is reached.

# 1. Evidence requiring the amendment

The FC-030.2C.3 real-SQL investigation established two facts about the frozen unique projection identity authority:

```text
UQ_OperationalMetricProjection_LogicalHash
(
    OperationalMetricProjectionProcessorRowId,
    EvaluationKeyHash
)
```

First, complete processor-prefix acquisition under:

```text
Serializable + UPDLOCK + HOLDLOCK
```

provides complete current-set discovery, existing/missing identity protection, empty-prefix phantom protection, and deterministic same-processor exclusion.

Second, SQL Server key-range protection at a composite-index processor boundary can transiently block a distinct processor even though the processors have independent logical state.

The later exact missing-slot diagnostic confirmed that this is not unique to the complete-prefix scan: above-last and empty-processor missing slots can also acquire a `RangeS-U` whose endpoint is a distinct processor key.

The decisive bounded conclusion remains:

> Neither complete-prefix locking nor exact missing-slot locking over the frozen `UQ_OperationalMetricProjection_LogicalHash` authority satisfies a zero-transient-blocking interpretation of processor-local concurrency for all valid projection states.

That physical-locality interpretation was stronger than the original logical independence requirement and is not required for correctness.

---

# 2. Amended concurrency authority

The following text is now the authoritative FC-030.2C.1 concurrency semantic:

> **Distinct processors have independent logical state and correctness authority. Implementations must not use a database-wide publication mutex or shared cross-processor correctness state. Incidental, bounded SQL Server key-range blocking between adjacent processor prefixes is permitted. It must not cause partial publication, state corruption, or checkpoint interference.**

This amendment distinguishes:

```text
logical independence
    REQUIRED

same-processor serialization
    REQUIRED

no database-wide publication mutex
    REQUIRED

no shared cross-processor correctness state
    REQUIRED

zero transient physical lock blocking between distinct processors
    NOT REQUIRED

bounded incidental SQL Server boundary blocking
    PERMITTED
```

The amendment does not permit correctness to depend on one processor's durable state belonging to another processor, nor does it permit a global mutex to serialize all publications by design.

---

# 3. Meaning of bounded incidental blocking

Permitted cross-processor blocking is a physical consequence of SQL Server key-range protection on the frozen composite unique index, not a correctness authority.

It is permitted only when all of the following remain true:

```text
1. Processor A owns only processor A durable state.
2. Processor B owns only processor B durable state.
3. Processor/checkpoint CAS semantics remain per processor.
4. A blocked distinct-processor writer can continue after the blocking transaction commits or rolls back.
5. Lock timeout/deadlock/cancellation before confirmed commit rolls back the victim publication completely.
6. Existing independent worker retry behavior may safely retry the victim.
7. No page/object/database-wide publication mutex is required for correctness.
8. Atomic publication remains processor-scoped in durable state, even if physical key-range waits overlap temporarily.
```

"Bounded" does not mean a fixed millisecond service-level objective is frozen here. It means the wait is tied to an owning SQL transaction/lock lifetime and must clear through normal commit, rollback, timeout, deadlock-victim handling, or cancellation semantics rather than through a permanent/shared global publication authority.

# 4. Selected projection acquisition protocol

Under the amended concurrency interpretation, the selected FC-030.2C.3 projection acquisition primitive is the complete processor-prefix acquisition already proven by real SQL:

```sql
SELECT ...
FROM dbo.OperationalMetricProjection WITH
(
    UPDLOCK,
    HOLDLOCK,
    INDEX(UQ_OperationalMetricProjection_LogicalHash)
)
WHERE OperationalMetricProjectionProcessorRowId = @ProcessorRowId
ORDER BY EvaluationKeyHash;
```

The query executes inside the existing SQL Server `Serializable` publication transaction after processor and checkpoint locks are held.

Its role is to establish the complete current projection set and protect existing and missing identities for one logical processor publication before manifest/evidence locks and before DML.

The previously observed cross-processor boundary contention remains valid evidence. It is **accepted as incidental bounded physical contention**, not reclassified as processor-local physical locking.

# 7. Preserved lock, DML, and publication order

This amendment does not change the frozen acquisition order:

```text
ProjectionProcessor key slot
    ↓
ProjectionCheckpoint key slot
    ↓
OperationalMetricProjection complete processor prefix / identity range
    ↓
OperationalMetricProjectionManifest rows
    ↓
OperationalMetricProjectionEvidence rows
```

Projection/manifest/evidence DML is permitted only after all required projection, manifest, and evidence locks have been acquired and validated in that order within the same transaction.

The implementation sequence is frozen as:

```text
1. Complete C.3 complete-prefix acquisition and validation.
2. Acquire C.4 manifest locks.
3. Acquire C.4 evidence locks.
4. Verify the full frozen lock sequence.
5. Execute projection/manifest/evidence DML.
6. Revalidate exact published state.
7. Advance checkpoint last.
8. Commit.
```

**No projection, manifest, or evidence DML may occur between steps 1–4.**

Once step 4 is satisfied, dependency-safe DML may execute while all previously acquired locks remain held. Checkpoint advancement remains last inside the same atomic SQL transaction.

No implementation may acquire manifest/evidence locks and then return to acquire an earlier projection-range lock.

# 8. Required acceptance additions before C.3/C.4 closure

The following real-SQL proofs are mandatory before FC-030.2C.3/2C.4 may close:

| Area | Required proof |
|---|---|
| Distinct-processor blocked successor | A distinct-processor writer blocked by an adjacent processor key range completes after the owner commits or rolls back. |
| Processor ownership | Both publications remain processor-correct and atomically isolated; no durable projection, manifest, evidence, or checkpoint crosses processor ownership. |
| Checkpoint independence | A distinct processor's checkpoint is neither advanced, rewritten, nor used as correctness state by the owner publication. |
| Atomic publication | Readers/verification observe only the previous complete publication or the new complete publication for each processor; never a partial/mixed accepted state. |
| Timeout/deadlock victim | A lock-timeout or deadlock-victim publication rolls back completely with no partial projection/manifest/evidence/checkpoint state. |
| Retry | The rolled-back victim succeeds through the existing independent worker retry/replay path without duplicate or divergent publication. |
| No escalation dependency | Correctness does not require page/object lock escalation and no database-wide publication mutex is introduced. |
| Same-processor successors | Competing successors for the same expected checkpoint still serialize; divergent successors cannot both publish. |
| Frozen lock order | The complete-prefix protocol continues to acquire locks in processor → checkpoint → projection → manifest → evidence order. |
| DML authorization boundary | No projection/manifest/evidence mutation occurs until the projection, manifest, and evidence lock sets have all been acquired and validated in the frozen order. |

These are closure proofs, not prerequisites for writing the DML implementation itself. The implementation is authorized to execute DML only on paths that have already satisfied the frozen lock boundary in the same transaction.

# 9. Failure and retry semantics

Existing FC-030.2C.1 failure representation remains unchanged.

In particular:

```text
semantic checkpoint/binding/collision/replay conflicts
    → InvalidOperationException

cancellation before confirmed commit
    → OperationCanceledException / derived

unexpected SQL provider failure
    → preserve SqlException unless authoritative reread proves a frozen semantic conflict
```

A SQL Server deadlock victim or lock-timeout is not evidence of partial publication authority. If it occurs before confirmed commit, the transaction must roll back completely and the existing worker retry/replay behavior must safely re-attempt from durable state.

No new public exception hierarchy is introduced by this amendment.

# 11. Re-freeze decision

FC-030.2C.1 is **CLOSED / FROZEN** with the narrow concurrency clarification and DML authorization boundary in this document.

The key concurrency distinction remains frozen as:

> **Logical processor independence is required. Zero transient physical SQL Server blocking between distinct processors is not required. Bounded incidental key-range blocking is permitted, provided correctness, ownership, atomicity, checkpoint independence, rollback, and retry semantics remain processor-safe.**

The DML boundary is frozen as:

> **Projection/manifest/evidence DML is authorized only after the implementation has acquired and validated all required projection, manifest, and evidence locks in the frozen order within the same transaction.**

The selected C.3 acquisition protocol remains the complete processor-prefix query on `UQ_OperationalMetricProjection_LogicalHash` under the existing `Serializable + UPDLOCK + HOLDLOCK` authority.

Migration 005 remains CLOSED / FROZEN.
