# FC-031.2C — Mapping Coverage Authority Closure

Status: **CLOSED / FROZEN**

Parent feature: **FC-031 — Authoritative Current Machine State**

## Closure boundary

FC-031.2C establishes the portable mapping-coverage authority required by authoritative current machine state. It closes the mapping-progress seam from durable raw observation consumption through canonical mapping publication, without authorizing state/activity continuity, authoritative current-state cut materialization, SQL current-state authority, semantic-reader, API, or dashboard work.

The portable contract is the semantic authority. The in-memory provider and mapping-processor integration are conformance implementations of that contract rather than independent specifications.

## Frozen outcomes

The completed slice establishes and proves the following authority:

- mapping authority is scoped by `ObservationProcessorId` and `ObservationStreamId`;
- `RawConsumedThrough` represents the greatest durable raw observation position successfully processed by mapping authority;
- `MappedEvaluationInputHighWater` represents the greatest durable raw position actually emitted as canonical/mapped evaluation input;
- unmapped raw observations advance raw coverage without inventing mapped-input coverage;
- mapped-input high-water may remain `null` until the first canonical/mapped observation is emitted;
- later unmapped progress preserves the prior mapped-input high-water;
- mapping authority revision allocation is provider-owned and deterministic;
- the first changed authority commit establishes revision `0`;
- subsequent changed authority commits advance revision monotonically;
- current exact replay is idempotent and does not advance revision;
- stale exact replay is accepted as lost-acknowledgement recovery and does not advance revision;
- stale conflicting proposals are rejected without mutation;
- processor/stream authority remains isolated;
- in-memory authority history is intentionally limited to provider instance lifetime;
- revision exhaustion rejects changed authority atomically while preserving legal exact replay;
- mapping publication occurs only after successful canonical output publication;
- mapping-authority publication failure prevents the generic FC-024 processing checkpoint from advancing;
- if mapping output succeeds but authority publication fails, replay converges through idempotent mapped-output publication and authority publication;
- if mapping authority succeeds but the generic processing checkpoint fails, replay converges without duplicating mapped output or advancing mapping revision;
- competing commits from the same expected authority permit exactly one conflicting CAS winner;
- Edge composition publishes the in-memory mapping authority as the current portable reference implementation without introducing SQL mapping authority.
