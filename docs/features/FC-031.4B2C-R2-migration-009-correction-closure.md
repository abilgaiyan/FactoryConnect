## Scope closed

This correction package repairs the durable-output identity defect discovered during the FC-031.4B.2C SQL joint-publication design trace.

Migration 008 introduced `MachineStateChangeHistory` and `MachineActivityPeriodHistory`, but those tables did not persist the portable durable-output `InstanceId` and `Sequence` identity. No valid invariant permits reconstructing those values after persistence.

Migration 008 is immutable because the canonical migration checksum and exact-prefix ledger make previously published migration bytes historical authority. The correction therefore uses a new Migration 009.

This package does not implement the FC-031.4B.2C SQL joint publication transaction. It establishes the corrected physical schema baseline required before that implementation resumes.

## Existing-data safety rule

Migration 008 cannot provide truthful values for the missing identity of already-persisted history rows. Migration 009 therefore fails fast rather than fabricating data.

Before any schema mutation, Migration 009 rejects a database containing rows in either:

```text
dbo.MachineStateChangeHistory
dbo.MachineActivityPeriodHistory
```

The failure uses SQL error number `51009`.

This safety rule is atomic. Failure leaves the database at exact Post008 state and does not record Migration 009 in the migration ledger.

## SQL Server compilation correction

The Migration 009 column additions and their dependent CHECK constraints execute inside the existing engine-owned migration transaction.

SQL Server resolves dependent column references at batch compilation time. The CHECK-constraint statements are therefore executed through dynamic SQL only to defer their compilation until after the preceding column additions have executed.

This changes no correction semantics and introduces no separate transaction boundary.
