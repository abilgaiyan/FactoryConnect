# 1. Decision question

The remaining architecture question is:

> Can migration 005, as frozen, satisfy all three FC-030.2C.1 requirements simultaneously: complete current-set ownership, SQL Server Serializable phantom protection for projection identities, and processor-local concurrency?

The whole-processor-prefix primitive has already answered **no for that query shape**. Its `RangeS-U` boundary protection conflicts with an adjacent processor prefix on the frozen composite unique index.

That finding is preserved and is not reopened here.

---

# 3. Option A — keep the complete processor-prefix range scan

Shape:

```sql
SELECT ...
FROM dbo.OperationalMetricProjection WITH
(
    UPDLOCK,
    HOLDLOCK,
    INDEX(UQ_OperationalMetricProjection_LogicalHash)
)
WHERE OperationalMetricProjectionProcessorRowId = @ProcessorRowId
ORDER BY EvaluationKeyHash;
```

Classification:

```text
complete current-set discovery         YES
same-processor phantom protection      YES
frozen index authority                 YES
projection-before-manifest order       YES
processor-local concurrency            NO — real-SQL failure
```

**Decision: REJECTED by existing evidence.**

This option is not eligible for further implementation work unless the frozen concurrency requirement changes.

---

# 4. Option B — exact incoming/current hash-slot acquisition only

Shape:

```text
lock exact known/current hashes
+ lock exact incoming hashes
in ascending EvaluationKeyHash order
```

This avoids intentionally scanning the complete processor prefix.

However, exact incoming hashes alone cannot discover obsolete currently published projections. A complete-set source is still required.

More importantly, an exact lookup for a **missing** composite key under `Serializable + UPDLOCK + HOLDLOCK` is still protected by SQL Server key-range locking. The missing-key range is defined by adjacent index entries, not by FactoryConnect processor semantics.

Therefore a missing exact hash at a processor boundary may still overlap an adjacent processor prefix even though the SQL predicate is an equality predicate.

Classification:

```text
existing exact identity locking        plausible
missing exact identity locking         plausible
complete current-set discovery         NO by itself
processor-local concurrency            UNPROVEN for boundary missing keys
```

**Decision: NOT YET ELIGIBLE.**

Before this primitive can participate in a replacement design, real SQL must prove that missing exact slots at the low/high processor boundaries do not block a distinct processor. If they do block, this option cannot satisfy frozen C.1 by itself.

---

# 5. Option C — manifest-assisted preflight + exact projection-slot acquisition

The manifest is already frozen as the exact complete published projection set for the durable checkpoint. That allows a possible design which does not use the projection table itself for complete-set discovery.

Conceptual sequence:

```text
PRE-FLIGHT — committed observational reconstruction

1. Read checkpoint C1.
2. Read exact manifest for C1.
3. Resolve the manifest projection identities/hashes.
4. Read checkpoint C2.
5. Accept preflight only if C1 == C2.

WRITER — existing C.2 Serializable transaction

6. Lock processor slot.
7. Lock checkpoint slot.
8. Require durable checkpoint == accepted preflight checkpoint.
   If not, rollback/restart preflight.
9. Lock union(current manifest hashes, incoming hashes)
   in ascending EvaluationKeyHash order.
10. Validate exact projection identities/state.
11. Lock manifest rows in frozen order.
12. Revalidate manifest == accepted preflight manifest.
13. Lock evidence.
14. Only then permit dependency-safe DML.
15. Advance checkpoint last.
```

Why this is architecturally interesting:

- complete-set discovery comes from the already-frozen manifest authority rather than an unbounded projection prefix;
- no manifest lock is acquired before projection locks inside the publication transaction;
- the checkpoint CAS slot prevents another same-processor publication from changing the accepted set after writer validation;
- a stale preflight becomes a retry, not mutation authority.

But this option still depends on **exact missing projection-slot acquisition** for incoming identities. Therefore it inherits Option B's unresolved boundary-gap question.

It also requires a precise contract interpretation: the preflight is observational committed-state discovery performed before the Serializable publication transaction, not an isolation downgrade inside that transaction. No mutation may rely on the preflight unless the writer subsequently locks and validates the same checkpoint and revalidates the manifest under the frozen order.

Classification:

```text
complete current-set discovery         YES — via frozen manifest authority
projection-before-manifest lock order   potentially YES
same-processor stability               potentially YES — checkpoint CAS
processor-local concurrency            UNPROVEN — missing exact-slot boundary
migration-005 change                    NO
C.1 amendment                           not selected / must be reviewed if interpretation is disputed
```

**Decision: STRONGEST CURRENT CANDIDATE, BUT NOT AUTHORIZED.**

It must not replace the blocker until the missing-slot boundary behavior is proven and the preflight interpretation is explicitly accepted as C.1-compatible.

---

# 6. Option D — rely on processor/checkpoint serialization and downgrade projection reads

Concept:

```text
processor/checkpoint lock acts as per-processor mutex
projection discovery/lookup uses weaker committed reads
no projection key-range phantom locking
```

This could preserve processor-local concurrency mechanically because the processor/checkpoint authority is already processor-local.

But it contradicts the frozen C.1 replacement authority, which requires the publication transaction to remain Serializable and projection identities to use `UPDLOCK, HOLDLOCK` semantics.

**Decision: REJECTED under current authority.**

This option requires an explicit C.1 architecture amendment before implementation and is not authorized in FC-030.2C.3.

---

# 7. Option E — processor-scoped application lock

SQL Server `sp_getapplock` can provide transaction-owned application resources and could create an explicit logical per-processor mutex.

However:

- application locks are not part of the frozen projection identity authority;
- they do not by themselves satisfy the frozen projection `UPDLOCK, HOLDLOCK` requirement;
- using them to replace the current lock semantics would change the C.1 concurrency mechanism;
- the blocker investigation explicitly did not authorize application locks as a workaround.

**Decision: OUT OF SCOPE under unchanged C.1.**

It may be considered only in a future contract-amendment pass.

# 9. Required next evidence — exact missing-slot boundary matrix

The architecture cannot yet choose Option B or C because the remaining SQL Server question is narrower than the already-proven prefix-scan failure:

> Does an exact missing `(ProcessorRowId, EvaluationKeyHash)` acquisition under the frozen `Serializable + UPDLOCK + HOLDLOCK + UQ_OperationalMetricProjection_LogicalHash` authority cross a distinct processor boundary?

The next evidence must be diagnostic / architectural proof only. No DML continuation is authorized.

Required real-SQL matrix:

```text
A. Existing key in processor A
   → lock exact existing identity
   → processor B exact existing key proceeds independently

B. Missing hash strictly between two existing hashes of processor A
   → same-processor contender excluded
   → processor B proceeds independently

C. Missing hash below processor A's first existing hash
   → capture granted/waiting KEY range resources
   → processor B independence must be proven

D. Missing hash above processor A's last existing hash
   → capture granted/waiting KEY range resources
   → processor B independence must be proven

E. Processor A has zero projection rows
   → exact missing-slot acquisition
   → capture whether next-key range reaches processor B

F. Adjacent processor prefixes in both logical directions
   → repeat boundary cases with A before B and B before A
```

For any blocked distinct-processor case, capture both sessions while the contender is waiting:

```text
sys.dm_tran_locks
    resource_type
    request_mode
    request_status
    resource_associated_entity_id
    resource_description

sys.dm_exec_requests
    wait_type
    wait_resource
    blocking_session_id
```

The decisive proof is shared/conflicting KEY range resource evidence on `UQ_OperationalMetricProjection_LogicalHash`, not merely a timeout number after the waiting request has disappeared.

No unrealistic row volume should be used; lock escalation is not part of the question.

---

# 10. Decision rule after the missing-slot matrix

If every exact missing-slot boundary case preserves distinct-processor independence:

```text
Option C becomes eligible for a narrow C.1-compatibility review
(manifest-assisted stable preflight + exact projection-slot locking).
```

It is still not automatically authorized; the preflight interpretation must be frozen before implementation.

If any exact missing-slot boundary case blocks a distinct processor because the required Serializable key range crosses the processor boundary:

```text
migration 005 + unchanged C.1 cannot currently demonstrate
processor-local projection identity phantom protection.
```

At that point FC-030.2C must remain stopped and the architecture decision must explicitly choose one of:

```text
amend C.1 locking semantics
or
reopen migration-005 physical authority
or
accept broader cross-processor serialization by changing the concurrency requirement
```

None of those choices is made by this document.
