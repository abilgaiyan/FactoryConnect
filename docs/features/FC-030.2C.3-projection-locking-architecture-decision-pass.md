# 1. Frozen decision question

The governing question was whether migration 005, as frozen, could satisfy all of these FC-030.2C.1 requirements simultaneously:

```text
writer isolation = SQL Server Serializable
projection identities protected with UPDLOCK + HOLDLOCK semantics
missing projection identities phantom-protected
projection identity authority = (ProcessorRowId, EvaluationKeyHash)
same-processor writers serialized
distinct processors logically independent
```

The complete processor-prefix primitive already failed the distinct-processor requirement.

The remaining candidate attempted to avoid the complete prefix and acquire only exact known/current/incoming projection identities. That candidate has now also been tested at the physical processor boundaries.

---

# 2. Frozen physical authority

Migration 005 remains unchanged and provides the unique projection identity authority:

```text
UQ_OperationalMetricProjection_LogicalHash
(
    OperationalMetricProjectionProcessorRowId,
    EvaluationKeyHash
)
```

The exact-slot diagnostic used:

```sql
SELECT OperationalMetricProjectionRowId, EvaluationKeyHash
FROM dbo.OperationalMetricProjection WITH
(
    UPDLOCK,
    HOLDLOCK,
    INDEX(UQ_OperationalMetricProjection_LogicalHash)
)
WHERE OperationalMetricProjectionProcessorRowId = @ProcessorRowId
  AND EvaluationKeyHash = @Hash;
```

No production persistence code, DML protocol, FC-030.2C.1 contract, or migration-005 object was changed for this proof.

# 3. Real-SQL exact-slot boundary matrix

The dedicated real-SQL diagnostic matrix completed successfully as a diagnostic harness:

```text
SqlServerOperationalMetricProjectionExactSlotBoundaryDiagnosticsIntegrationTests
6 / 6 passed
```

The test success means all diagnostic scenarios executed and released correctly; it does **not** mean all concurrency cases were independent.

Observed matrix:

```text
existing A key -> existing B key                 INDEPENDENT
internal missing A hash -> existing B key        INDEPENDENT
below-first missing A hash -> existing B key     INDEPENDENT
reverse below-first B hash -> existing A key     INDEPENDENT
empty processor A missing hash -> existing B     BLOCKED
above-last missing A hash -> existing B          BLOCKED
```

The matrix therefore proves that exact equality predicates improve locality for some identities and gaps, but they do not provide processor-local behavior for every valid projection state.

---

# 4. Existing and internal identity behavior

An exact existing identity in processor A acquired:

```text
KEY | U | GRANT | UQ_OperationalMetricProjection_LogicalHash
```

while the distinct processor B existing-key acquisition completed independently.

A missing hash strictly inside a populated processor A range acquired `RangeS-U` phantom protection while processor B still completed independently.

The observed below-first cases also remained independent in both tested processor directions.

These cases establish that cross-processor contention is not caused by every exact lookup and is not an object/page-wide serialization effect.

---

# 5. Empty-processor boundary failure

For an exact missing identity in a processor with zero projection rows, the owner held:

```text
KEY | RangeS-U | GRANT
index = UQ_OperationalMetricProjection_LogicalHash
resource = (c8c18169224b)
```

The distinct-processor contender simultaneously reported:

```text
KEY | U | WAIT
index = UQ_OperationalMetricProjection_LogicalHash
resource = (c8c18169224b)
```

`sys.dm_exec_requests` captured the live wait:

```text
wait_type           = LCK_M_U
wait_resource       = KEY: 6:72057594049462272 (c8c18169224b)
blocking_session_id = 52
status              = suspended
```

The granted `RangeS-U` and waiting `U` therefore refer to the same key resource on the frozen logical-hash index.

This is direct evidence that exact missing-slot phantom protection for an empty processor can cross into a distinct processor's physical key boundary.

Again, the granted owner range and waiting contender identity are the same key resource.

The failure is therefore not inferred merely from a timeout. The physical conflict was captured while the contender was waiting.

# 7. Architectural interpretation

The composite physical order is:

```text
(OperationalMetricProjectionProcessorRowId, EvaluationKeyHash)
```

For an existing identity, SQL Server can grant a `U` lock on that exact key.

For a missing identity under `Serializable + UPDLOCK + HOLDLOCK`, SQL Server protects the relevant key range. At a processor's terminal boundary, the next physical index key can belong to a different processor. An empty processor has no existing processor-local projection key that can bound the missing identity range.

Consequently, an exact equality predicate does not guarantee a processor-local physical lock range.

The matrix establishes this for normal valid publication states:

```text
initial publication into an empty processor
new projection identity above the processor's current maximum hash
```

Those states cannot be excluded from FC-030.2C persistence semantics.

---

# 8. Decisive architecture conclusion

The following wording is now authoritative:

> Neither complete-prefix locking nor exact missing-slot locking over the frozen `UQ_OperationalMetricProjection_LogicalHash` authority satisfies the frozen processor-local concurrency requirement for all valid projection states. No compliant C.3 acquisition protocol against the current frozen authority has been established.

This conclusion is intentionally bounded.

It does **not** claim that every conceivable SQL Server schema or concurrency protocol is impossible. It establishes that the investigated acquisition mechanisms cannot satisfy the unchanged C.1 requirements against the current frozen physical authority for all required states.
