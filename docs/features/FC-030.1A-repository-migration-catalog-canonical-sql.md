# FC-030.1A — Repository Migration Catalog & Canonical SQL

## Status

**Implementation complete on feature branch; repository regression evidence pending.**

FC-030.1A is repository-only infrastructure. It does not connect to SQL Server and does not introduce a migration ledger, migration execution, schema descriptors, migration 005, operational-metric SQL persistence, or reporting schema changes.

## Construction invariant

```text
embedded migration bytes
    ↓
strict canonical SQL bytes
    ↓
lexical policy validation
    ↓
immutable migration descriptor
    ↓
validated deterministic repository catalog
```

For every migration descriptor, the exact canonical byte sequence hashed by SHA-256 is retained by the descriptor and is the byte sequence a later migration executor must submit unchanged to SQL Server.

## Frozen migration resource grammar

Only manifest resources under:

```text
FactoryConnect.Persistence.SqlServer.Sql.
```

participate in SQL migration discovery.

Every `.sql` resource discovered under that namespace must parse according to:

```text
FactoryConnect.Persistence.SqlServer.Sql.<three-digit-id>_<name>.sql
```

where:

```text
MigrationId   = exactly three ASCII digits
Name          = non-empty ASCII filename component using letters, digits, '-' or '_'
ResourceName  = exact manifest resource name
```

Malformed migration-namespace SQL resources fail catalog construction. They are never silently omitted after discovery.

Catalog identity is exact and deterministic. Migration ids, migration names, and resource names are unique. The resulting catalog is ordered by migration id and ids must be strictly increasing.

## Closed transaction policy

The transaction-policy vocabulary is closed:

```text
EngineOwned
LegacyMigration003Embedded
```

The only migration permitted to receive `LegacyMigration003Embedded` is the exact identity:

```text
003_BindMetricInputFactMachine
```

Therefore the current repository contract is:

```text
001_InitialObservationIngestion          → EngineOwned
002_DurableMetricAggregation             → EngineOwned
003_BindMetricInputFactMachine           → LegacyMigration003Embedded
004_ProductionContextMetricInputHandoff  → EngineOwned
future migrations                        → EngineOwned
```

The exception is derived from exact migration identity during catalog construction; callers cannot grant it by configuration.

This intentionally subjects 001, 002, and 004 to the same no-transaction-control lexical policy as future engine-owned migrations. A historical edit that adds transaction control to one of them must fail catalog construction rather than silently expanding the legacy exception.

## Canonical SQL bytes

Canonicalization is limited to byte/text representation and performs no SQL rewriting or Unicode normalization.

The canonicalizer must:

```text
accept zero or one UTF-8 BOM at byte offset zero
remove that one leading BOM when present
decode the remainder as strict UTF-8
reject malformed UTF-8
normalize CRLF → LF
normalize CR → LF
preserve whether a final newline exists
encode canonical bytes as UTF-8 without adding a BOM
preserve U+FEFF occurring after byte offset zero
perform no other Unicode normalization
compute SHA-256 over the exact canonical bytes retained for execution
```

If input begins with more than one BOM byte sequence, only the byte-offset-zero BOM has BOM semantics. Any following decoded U+FEFF remains content and is not stripped.

## Lexical-region contract

FC-030.1A uses a narrow SQL lexical scanner, not a T-SQL parser.

The scanner distinguishes executable SQL from:

```text
single-quoted string literals
quoted identifiers
bracket identifiers
line comments
nested block comments
```

Escaping rules covered by the scanner include:

```sql
'it''s'
"a""b"
[a]]b]
```

Nested block comments are supported. A line comment ending at EOF is valid.

The following unterminated regions are repository validation failures:

```text
string literal
quoted identifier
bracket identifier
block comment
```

Ambiguous SQL must never reach a later migration executor.

## Executable GO policy

Executable `GO` detection is line-oriented, case-insensitive, and applies only outside non-executable lexical regions.

The following are rejected:

```sql
GO
  go
GO 2
GO -- comment
GO;
GO 2;
```

`GO;` is rejected conservatively even though it is not a valid sqlcmd batch separator because it strongly indicates an erroneous batch directive in an application-owned migration resource.

The following do not represent batch directives and are allowed:

```sql
SELECT GO FROM Example;
SELECT [GO];
SELECT 'GO';
SELECT "GO";
-- GO
/* GO */
```

## Engine-owned transaction-control policy

For `EngineOwned` migrations, executable transaction-control statements are prohibited case-insensitively across arbitrary whitespace, newlines, and comments between tokens.

The recognized prohibited forms include:

```text
BEGIN TRANSACTION
BEGIN TRAN
COMMIT
COMMIT TRANSACTION
COMMIT TRAN
ROLLBACK
ROLLBACK TRANSACTION
ROLLBACK TRAN
SAVE TRANSACTION
SAVE TRAN
```

Occurrences inside strings, quoted identifiers, bracket identifiers, line comments, or block comments are ignored as non-executable text.

Migration 003 remains subject to all lexical well-formedness and executable-GO rules; only its transaction-control check is grandfathered.

## Deterministic catalog contract

Catalog construction performs this sequence:

```text
enumerate migration-namespace SQL resources
    ↓
parse exact resource identity
    ↓
read embedded bytes
    ↓
canonicalize bytes
    ↓
derive closed transaction policy from identity
    ↓
validate executable GO
    ↓
validate transaction policy
    ↓
construct immutable descriptor
    ↓
sort deterministically
    ↓
validate catalog uniqueness/order/003 identity
```

Each descriptor retains:

```text
MigrationId
Name
ResourceName
TransactionPolicy
CanonicalSql
CanonicalBytes
Sha256Checksum
```

`CanonicalSql` and `CanonicalBytes` are two views of the same canonical content; SHA-256 is computed from `CanonicalBytes`.

```text
✗ SQL metadata inspection
✗ migration history table
✗ sp_getapplock

✗ schema classification
✗ LegacyPost004SchemaDescriptor

✗ deployment migration command

```

Those remain later FC-030.1 slices or later FC-030 work.
