## Identity and responsibility

Use the reserved policy `planned-production-availability/v2`, projection processor `operational-metrics:{MachineId:D}:builtins-v2-planned-production-availability-v2`, Availability definition key `availability` version `2`, and evidence policy `planned-production-availability-evidence/v2`.
These are reserved design identities, not executable registrations or codec support.

C3 is a pure consumer of C1-verified authority and C2-constructed operands. It does not query current schedules, infer completeness from data rows, intersect raw intervals, repair evidence, choose a newer cut, or recompute missing operands from aggregates.
The future composition root must admit only the verified reconstruction result; arbitrary public records and caller-provided verified=true flags are not a trust boundary. C4 independently reconstructs and validates before durable publication.

V1 ActualProductionTime, builtins-v1 and the existing availability-containment-v1 evaluator/publisher remain unchanged. Outside-plan running is preserved under V2 and is not by itself a V2 Availability failure. V1's RunningOutsidePlannedProduction containment remains active under its existing identity.

## Input and result shapes (logical contracts)

An admitted request includes the full evaluation subject, exact source revision, schedule authority, C1 outcome, C2 operand admission states, canonical provenance manifest identity and all applicable conflicts/missing-authority details.
Each operand is either Complete(value, exact ticks, unit, provenance) or Absent(reason, evidence extent). Partial diagnostics are a distinct type/state and cannot satisfy a required Complete operand.

Required numeric operands: EligibleRunningDuration and PlannedOperatingTime. TotalRunningDuration and ExcludedRunningDuration are independent diagnostics and never fallback inputs.
A result binds the same subject/cut/definition/policy, status, nullable ratio, reason and reason operand, admitted operand evidence, authority/provenance references and deterministic diagnostic inventory.
C4 decides the encoded representation and whether a versioned envelope is required. Current V1 containment format cannot be assumed compatible.

## Status decision order

Evaluate all available input integrity/contradiction checks before choosing an ordinary missing-evidence or zero-denominator result. Do not ignore a known contradiction because another receipt is missing.
Infrastructure errors, cancellation, unavailable exact historical revision, unsupported required encoding or corrupt durable receipt propagate as explicit operation/read failures; they are not a successful unavailable metric or proof of rollback.

| Order | Condition | Result |
| --- | --- | --- |
| 1 | Wrong subject/cut/policy, forged provenance, contradictory retained payload or malformed typed request | Reject request/read/publication; no evaluation result |
| 2 | Established semantic eligibility conflict or invalid source interval set | Unavailable / ConflictingEligibility or InvalidIntervalEvidence; null ratio |
| 3 | Complete admitted operands violate nonnegative or eligible<=planned invariants | Unavailable / AvailabilityOperandInvariantViolation; null ratio; no clamp |
| 4 | Required historical schedule authority or extent missing | InsufficientEvidence / MissingSchedule; null ratio |
| 5 | C1 proves complete authoritative planned set is empty, without known contradictions | Unavailable / NoPlannedProduction; null ratio; activity completeness not required |
| 6 | Nonempty P with required eligibility authority missing/indeterminate | InsufficientEvidence / MissingEligibility; null ratio |
| 7 | Nonempty P with activity gaps, unresolved classification/continuity or missing completion boundary | InsufficientEvidence / IncompleteActivityCoverage; null ratio |
| 8 | Authority verified but required C2 operand/provenance absent or unit/dimension inconsistent | Internal contract failure; reject, do not invent an operand |
| 9 | Both numeric operands Complete, denominator>0 and invariant valid | Calculated; eligible/planned in [0,1], including exact zero |

Do not compare incomplete diagnostic values to planned time for order 3. An unknown total-running operand is absent, not a negative value or zero.
A claimed VerifiedPlannedActivity outcome with missing required operands is internally inconsistent (order 8). An honest insufficient-authority reconstruction uses orders 4/6/7.
A claimed zero-plan outcome with a Complete positive eligible operand is contradictory and fails before order 5.
Unknown activity with a proven empty P satisfies order 5. Missing schedule plus absent running inputs satisfies order 4, never order 5.
These semantic reason names remain design reservations; concrete enums/API contracts need implementation review.

If several semantic problems exist at the same precedence level, retain all diagnostics and choose the primary reason deterministically: ConflictingEligibility before InvalidIntervalEvidence; MissingSchedule before MissingEligibility before IncompleteActivityCoverage. Evidence within a reason follows C2 canonical ordering.
Typed invariant failures take precedence only when their operands are independently admitted Complete; absent or partial operands cannot fabricate an invariant violation.

## Formula and precision

Availability = EligibleRunningDuration / PlannedOperatingTime.
Compare exact tick totals for invariant checks. Decimal-second values must exactly match the tick totals under C2 conversion; inconsistent representations reject the request.
Use checked decimal division without intermediate operand rounding; a non-terminating rational is represented by the deterministic .NET decimal division result. Retain original tick totals so the rational remains reconstructible.
The logical value is a dimensionless ratio; percentage multiplication, display rounding and formatting belong to presentation. A logical value slightly above one must never be rounded/clamped into acceptance.
No epsilon, average of shift percentages, inferred machine-on duration or aggregate subtraction is permitted.
A production-day result is independently reconstructed from that day's disjoint interval set at its bound cut, not computed as an unweighted average of shift Availability.

## Independent operand admission

C2-R1: PartialEstablishedFragments diagnostics cannot be passed as Complete TotalRunningDuration, EligibleRunningDuration or PlannedOperatingTime. The future type system and runtime validators must enforce this.
C2-R2: Every intersected fragment retains source identity, clipped endpoints and split-boundary authority. Evaluator evidence must reference that manifest unchanged; it cannot replace it with aggregate first/last timestamps.
Complete planned activity with unknown activity outside P may calculate Availability while TotalRunningDuration stays absent.
Zero planned time does not imply machine stopped, no running, complete activity coverage or 0% Availability.
Excluded running alone does not imply eligibility conflict when it agrees with historical exclusion authority.

## Version and dependency isolation

Select V2 explicitly by its canonical processor/definition/policy. Reject aliasing V1 data under a V2 ID, fallback to V1 after V2 failure, mixed operand cuts, or latest-processor lookup in place of exact-target reads.
Same machine/date may legitimately hold legacy calculated/unavailable outcomes and V2 outcomes independently. Do not overwrite or reinterpret legacy rows/checkpoints.
This design activates Availability only. V2 OEE, Performance, Utilization and assumed-quality dependency composition remain outside scope; no product result is inferred by multiplying an unreviewed mix of dependency versions.
If V2 OEE is later proposed, it requires a separate coherent dependency contract and explicit unavailable/insufficient propagation. Dashboard source changes remain separately authorized deployment work.

## Required acceptance cases (not executed)

| Case | Expected |
| --- | --- |
| Complete eligible=30, planned=60 | Calculated 0.5 |
| Complete eligible=0, planned=60 with non-running coverage | Calculated 0 |
| No running row, planned activity gap | InsufficientEvidence, not 0 |
| Proven empty P and unknown machine activity | NoPlannedProduction, no total-running claim |
| Missing schedule and unknown activity | MissingSchedule |
| Known conflicting eligibility with empty P | Conflict before no-production |
| Complete eligible>planned or negative operand | Invariant failure without clamp |
| Partial excluded diagnostic passed as eligible operand | Reject typed/admission mismatch |
| Complete planned activity, unknown outside P | Calculated with absent complete total |
| Different machine, revision, policy, unit or forged manifest | Reject incoherent request |
| Legacy outside-plan conflict and V2 valid eligible operands | Independent results; V1 unchanged |
| Reordered diagnostics and evidence | Same primary reason and canonical manifest references |
| Repeating decimal division, sub-second ticks, exact ratio one | Deterministic value; original exact ticks retained |
| Cancellation, missing exact cut or corrupt receipt | Propagate operation failure; no plausible metric |
| V2 unavailable but V1 calculated | No fallback or automatic dashboard substitution |
