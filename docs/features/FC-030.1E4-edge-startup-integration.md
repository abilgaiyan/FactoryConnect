## Goal

Make Edge hosted-service activation depend on the same provider-neutral persistence startup gate used by the API:

```text
HostApplicationBuilder
    → existing Edge application composition
    → builder.Build()
    → establish pre-activation process-shutdown cancellation
    → IPersistenceStartupGate.EnsureReadyAsync(...)
    → dispose pre-activation shutdown registrations
    → only after success: host.RunAsync()
```

The Edge entry point contains no SQL provider checks, migration logic, runtime compatibility logic, or host-specific persistence semantics.

## Central invariant

No Edge hosted service may start before the selected persistence startup gate succeeds.

This includes all workers registered by Edge application composition, including acquisition, observation processing, production metric input, aggregation, roster materialization, and operational-metric processing workloads.

A migration operational failure, verification operational failure, non-compatible database result, or cancellation therefore prevents `IHost.StartAsync` from being reached.

## Host integration

`Program.cs` now performs:

```text
builder.Services.AddFactoryConnectEdgeApplication(...)
builder.Services.AddSingleton<IEdgeStartupCancellationRegistrationFactory, EdgeStartupCancellationRegistrationFactory>()

host = builder.Build()

EdgePersistenceStartup.RunAsync(
    host.Services,
    () => host.RunAsync())
```

`EdgePersistenceStartup`:

1. resolves the pre-activation cancellation-registration factory from the built service provider;
2. creates the pre-activation cancellation registration;
3. resolves `IPersistenceStartupGate` from the built service provider;
4. awaits readiness with the pre-activation token;
5. disposes the temporary process-signal registration in `finally`;
6. invokes the host-run delegate only after readiness succeeds; and
7. does not catch or reinterpret readiness failures.

The helper is orchestration only and contains no SQL-specific code.

## Pre-activation cancellation ownership

As with the API, normal Generic Host lifetime signal handling is not yet active while the persistence gate is running.

`EdgeStartupCancellationRegistration` therefore temporarily observes:

```text
Console.CancelKeyPress
SIGTERM when supported
```

Both request cancellation of the startup token and suppress immediate termination long enough for the gate to observe cancellation.

The registration is disposed before `host.RunAsync()` begins, so normal Generic Host lifetime handling owns shutdown after activation.

Any `OperationCanceledException` emitted by C, D, or the selected startup gate propagates unchanged through the Edge entry point.

## Hosted-worker proof

`EdgePersistenceStartupTests` uses a real `IHost` with a probe `IHostedService` rather than merely checking a boolean run delegate.

The focused matrix proves:

1. readiness executes before `IHostedService.StartAsync`;
2. successful readiness allows the hosted service to start exactly once;
3. readiness failure propagates unchanged and leaves worker `StartCount == 0`;
4. readiness cancellation propagates unchanged and leaves worker `StartCount == 0`;
5. an already-cancelled pre-activation token reaches the startup gate and leaves worker `StartCount == 0`; and
6. the temporary cancellation registration is already disposed when the first hosted service starts.

These tests do not require SQL Server. Real C/D execution, API+Edge concurrent startup serialization, lock-timeout behavior, retry, and whole-host SQL conformance remain E.5.

## Provider neutrality

E.4 consumes only `IPersistenceStartupGate`.

Therefore:

```text
InMemory selected
    → selected provider supplies E.2 no-op gate
    → readiness completes
    → normal Edge workers start

SQL Server selected
    → selected provider supplies concrete C → D gate
    → workers start only after Compatible
```

No provider-name normalization or SQL option binding is duplicated in Edge.

## Hard boundary

E.4 does not:

- modify C migration semantics;
- modify D compatibility semantics;
- duplicate SQL migration or verification code;
- inspect `Persistence:Provider` in `Program.cs`;
- introduce migration 005;

- perform real-SQL concurrency proof.
