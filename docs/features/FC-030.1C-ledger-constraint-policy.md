# FC-030.1C — Ledger Constraint Policy Clarification

## Status

**FROZEN / NORMATIVE ADDENDUM**

This addendum resolves the final wording ambiguity in the FC-030.1C architecture contract at commit `599c1ea09b41dd37650dc7a32a35e831a97d72d6`.

Where the main FC-030.1C contract states that no default constraint is required and that check constraints may be frozen later in C.1, this addendum supersedes that wording with the following exact policy.

## Physical ledger constraint policy

The valid `dbo.FactoryConnectMigrationHistory` table has exactly:

```text
the four frozen columns
PK_FactoryConnectMigrationHistory
no additional columns
no additional primary/unique constraints
no foreign keys
no default constraints
no check constraints
no ordinary indexes
no triggers
```

Default constraints are therefore **not optional**. Any default constraint on the migration ledger makes its infrastructure shape invalid.

Check constraints are also **not part of the FC-030.1C physical ledger contract**. C.1 must not introduce checksum-format or UTC-offset check constraints without returning to architecture review.

A same-name user table containing a default constraint or any check constraint is:

```text
MigrationLedgerSchemaInvalid
```

The migration engine must not repair, drop, replace, or normalize that table.

## Row semantic validation

The following invariants are enforced by the ledger history reader rather than by physical SQL check constraints.

### CanonicalChecksum

A persisted checksum must satisfy all of the following:

```text
length == 64 characters
every character is one of 0-9 or A-F
text comparison is exact under the frozen BIN2/ordinal contract
casing participates in identity
no trimming
no uppercasing/lowercasing
no normalization
```

The repository catalog's frozen SHA-256 values use uppercase hexadecimal text; lowercase or mixed-case persisted text is invalid history even when it denotes the same hexadecimal bytes.

### AppliedAtUtc

A persisted `AppliedAtUtc` value must have:

```text
offset == +00:00
```

The engine writes values from the injectable UTC time source. Existing non-zero-offset values are invalid history and are not normalized by the reader.


FC-030.1C.1 must not introduce any physical default or check constraint on the ledger.

FC-030.1C.2+ remains unstarted until C.1 is implemented, reviewed, and frozen.
