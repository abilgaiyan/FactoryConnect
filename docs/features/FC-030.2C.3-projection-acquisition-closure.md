# 1. Governing authority remains unchanged

FC-030.2C.1 still freezes:

> **Logical processor independence is required. Zero transient physical SQL Server blocking between distinct processors is not required. Bounded incidental key-range blocking is permitted, provided correctness, ownership, atomicity, checkpoint independence, rollback, and retry semantics remain processor-safe.**

The DML authorization boundary remains:

> **Projection/manifest/evidence DML is authorized only after the implementation has acquired and validated all required projection, manifest, and evidence locks in the frozen order within the same transaction.**

No architecture decision is reopened by this test correction.

---

# 2. Selected C.3 acquisition remains unchanged

The authoritative production first access to `dbo.OperationalMetricProjection` remains:

```sql
SELECT ...
FROM dbo.OperationalMetricProjection WITH
(
    UPDLOCK,
    HOLDLOCK,
    INDEX(UQ_OperationalMetricProjection_LogicalHash)
)
WHERE OperationalMetricProjectionProcessorRowId = @ProcessorRowId
ORDER BY EvaluationKeyHash;
```

It executes inside the existing SQL Server `Serializable` publication transaction after processor and checkpoint acquisition.

The preparation boundary remains:

```text
compile and validate incoming identities
→ acquire complete processor prefix
→ acquire missing incoming slots in ascending hash order
→ validate complete current set
→ validate exact persisted identity/state
→ return mutation plan
```

C.3 performs no projection, manifest, evidence, or checkpoint DML.

# 4. Required authoritative bounded-contention proof

Before FC-030.2C.3 can close again, the production-path real-SQL test must prove all of the following:

```text
1. writer B enters the C.2 transaction body immediately before PrepareAsync;
2. writer A and writer B SQL session IDs are captured from their live transaction connections;
3. while A holds completed C.3 preparation, sys.dm_exec_requests reports B in a live LCK_M_* wait;
4. B's blocking_session_id equals A's session ID;
5. B's wait_resource is a KEY resource;
6. B has a waiting KEY lock whose HoBT/index resolves to UQ_OperationalMetricProjection_LogicalHash;
7. A is released through commit or rollback;
8. B then completes production PrepareAsync;
9. cleanup is protected by try/finally so A cannot remain held after an assertion failure.
```

A short timing timeout may remain only as a guard. It is not the authoritative concurrency proof.
