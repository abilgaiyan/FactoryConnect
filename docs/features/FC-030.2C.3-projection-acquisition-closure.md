This document closes the FC-030.2C.3 projection acquisition boundary after the FC-030.2C.1 concurrency-semantics amendment and the focused production-path real-SQL proof.

It does **not** close FC-030.2C as a whole, does not close FC-030.2C.4, does not authorize DML before manifest and evidence locks are acquired, does not alter migration 005, and does not weaken `Serializable + UPDLOCK + HOLDLOCK` authority.

# 1. Governing amended authority

FC-030.2C.1 now freezes the concurrency distinction as:

> **Logical processor independence is required. Zero transient physical SQL Server blocking between distinct processors is not required. Bounded incidental key-range blocking is permitted, provided correctness, ownership, atomicity, checkpoint independence, rollback, and retry semantics remain processor-safe.**

The DML boundary remains:

> **Projection/manifest/evidence DML is authorized only after the implementation has acquired and validated all required projection, manifest, and evidence locks in the frozen order within the same transaction.**

Therefore C.3 is responsible only for projection acquisition, complete-current-set discovery, identity validation, and preparation of the later mutation plan. C.3 must not mutate projection, manifest, or evidence state.

---

# 2. Frozen C.3 acquisition primitive

The selected first access to `dbo.OperationalMetricProjection` is the complete processor-prefix acquisition on the frozen migration-005 logical-hash authority:

```sql
SELECT ...
FROM dbo.OperationalMetricProjection WITH
(
    UPDLOCK,
    HOLDLOCK,
    INDEX(UQ_OperationalMetricProjection_LogicalHash)
)
WHERE OperationalMetricProjectionProcessorRowId = @ProcessorRowId
ORDER BY EvaluationKeyHash;
```

It executes inside the existing `Serializable` publication transaction after the processor and checkpoint serialization slots have been acquired.

The acquisition provides the complete current durable projection set for the processor and retains the necessary row/key-range protection until transaction end.

Incoming identities missing from the acquired current set are probed in ascending evaluation-key-hash order using the same frozen logical-hash authority. Exact persisted codec/hash/binary identity validation remains mandatory.

# 3. C.3 preparation result

`SqlServerOperationalMetricProjectionRows.PrepareAsync` is frozen at this boundary as preparation-only behavior.

It:

```text
compile incoming provider-neutral projections
validate duplicate/collision-free incoming identity set
acquire complete current processor prefix under Serializable + UPDLOCK + HOLDLOCK
acquire missing incoming identity slots in ascending hash order
validate complete current-set stability
validate persisted codec/hash/binary identity
validate structured persisted identity
validate replay state when reconciling equal revision
classify proposed existing/new rows
classify obsolete current projection rows
return a mutation plan
```

It does **not** perform:

```text
projection INSERT / UPDATE / DELETE
manifest INSERT / DELETE
evidence INSERT / DELETE
checkpoint advancement
```

The returned mutation plan is therefore not publication. It is input to the later C.4 lock-and-DML boundary inside the same transaction.

FC-030.2C.3 is **CLOSED / FROZEN** at the projection acquisition/preparation boundary.

The frozen result is:
