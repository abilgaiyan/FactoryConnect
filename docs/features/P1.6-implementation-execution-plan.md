## IMP-1 — Historical availability is the first feasibility gate

Prepare a repository-backed field/source matrix for schedule assignments and overrides, contextualized activity outputs, eligibility outputs, metric facts/contributions, producer publication/checkpoints, raw observation references and coverage receipts.
For each authority record state: exact identity/revision, payload location, retention, writer/transaction owner, immutable membership evidence, machine/period binding, migration version and independently resolvable dependency.

Resolve C1-R1 with a concrete durable output-to-aggregation-cut relation, including non-running authority without a corresponding metric fact. Observation and aggregation position domains remain distinct.
Distinguish code capability from data availability. Repository inspection cannot establish that a GG-003 backup actually contains the required historic payloads.
After separate authorization, use read-only inventory of a disposable restore to collect exact sample IDs/positions, orphan/absence evidence, producer membership and retention gaps. No replay, backfill, checkpoint changes or production-server queries are included in this plan.
If data access is unavailable, mark historical feasibility NotEstablished; do not assume it from schema presence.

Required decision per evidence category: AvailableAndVerifiable, AbsentAtHistoricalCut, RetainedReferencePayloadMissing, Conflicting, or NotEstablished.
Absent authority may support a future InsufficientEvidence result; lost referenced payload is integrity failure. No current configuration fallback or fabricated historical receipt.

Exit artifact: reviewed binding specification and a historical feasibility matrix. If evidence is absent, explicitly choose whether prospective-only implementation remains useful; never promise historic numeric Availability. Advancing to IMP-2 design does not change missing authority into available authority.

## IMP-2 — Schedule and activity verification

Resolve C1-R2: persist/resolve positive complete schedule selection, approved empty-production decision, effective assignment/override versions, timezone expansion and break policy. Distinguish empty selection from absent configuration.
Resolve C1-R3: exact coverage subject/revision reads, independent reference payload verification, completion boundaries, continuity/mapping/source-instance changes and missing/corrupt receipt taxonomy.
Define a concrete verifier input/output and durable membership/authority receipts using IMP-1's available sources. Do not accept a structurally Complete assessment as sufficient.
Prove activity partition equality with the planned union; classify middle gaps and unknown state explicitly. Missing activity outside planned production blocks complete total-running claims, not valid Availability.
Retain exact authority for NoPlannedProduction without claiming machine activity completeness.

Exit artifact: reviewed receipt producer/verifier specification plus independent test vectors for complete zero, middle gap, unknown eligibility, empty schedule and cross-cut substitution. Every unimplemented producer/retention prerequisite must have an explicit owner/package before IMP-3 integration.

## IMP-3 — Pure builder and evaluator

Implement only after separate authorization. C1-verified types feed C2 construction; partial diagnostics cannot satisfy complete operands (C2-R1).
Preserve original source IDs, clipped endpoints and boundary authority through every intersection (C2-R2).
Enforce C3-R1 typed separation of missing authority, semantic conflict, historical integrity, unsupported encoding and infrastructure failure.
Enforce C3-R2 exact-tick comparison and decimal behavior: repeating fractions, sub-second ticks, equality, checked overflow and original tick provenance.
Characterize input order invariance, cutoff/break splits, complete planned zero, unknown outside P, overlap/duplicates, wrong cut/policy and unchanged V1 mappings.
No production DI registration, SQL publisher, default processor changes, OEE dependency composition or dashboard source switch.

Exit evidence: pure test results and explicit compatibility review; synthetic vectors do not establish GG-003 completeness.

## IMP-4 — Formats, SQL and completion receipt

Freeze exact tags, endianness, string encoding, decimal canonicalization, presence markers, payload/dependency size limits and decoder rejection rules before database publication.
Use independently authored encoder/decoder vectors, not round-trip-only tests. Cover full position domain, Unicode, absent/empty, malformed lengths, depth/cycles, digest collision simulation, ticks and decimal representations.
Review physical schema, unique logical slots, immutable archive/dependency links, source revision/processor guards and retention constraints through repository-owned migrations.

Resolve C4-R2 with a durable completion receipt: processor/source/policy/format, exact revision, complete manifest and batch-content identities, expected predecessor, resulting checkpoint/manifest and canonical receipt identity. Define atomic insertion, identical replay, contradictory receipt rejection and uncertain-commit reconciliation.
A connection failure is an unknown commit outcome. Receipt lookup/reconstruction must prove completion before retry can report success; superseded-predecessor behavior must not move the checkpoint backwards.
Resolve C4-R3 with explicit transitive source-retention or immutable-equivalent archive policy, provenance of archived authority, exact reads after source archival and fail-closed behavior for lost dependencies.

Exit evidence: reviewed codecs/schema/receipt contracts and tests. Schema availability is not permission to activate publication or migrate production.

## IMP-5 — Transaction owner, locks and readers

Choose one owner for the complete verification/publication transaction; helpers must not silently commit independently. Independent reconstruction and final publication share a stable authority view.
Resolve C4-R1 with an actual lock graph covering V2 publication/readers, aggregation, context producers, schedule admission, coverage updates, V1 publication and retention. Document row/key-range/application locks and ordering, including absence proofs.
Serializable is not evidence of deadlock freedom. Run deterministic real-SQL interleavings for source advancement, authority admission, identical/conflicting writers, shared proofs/witnesses, readers versus commit and retention.
Inject faults at every archive/link/result/index/manifest/checkpoint stage; no partially visible publication. Test replay after uncertain commit, superseded predecessor, corrupt receipt and exact manifest conflict.
Verify exact-target readers distinguish Absent/Unavailable/UnsupportedEncoding/Corrupt from metric statuses, reproduce C1-C3 from retained authority, and never fall back to V1.

Exit evidence: lock-order acceptance, transactional/concurrency suite results, independent reader reconstruction, V1 regression and retention tests. CI status must be reported precisely; do not wait/poll unless requested.

## IMP-6 — Disposable restore only

Requires an identified disposable GG-003 restore, preserved source backup identity, accepted implementation commit and explicit replay authorization.
Capture baseline source/processor/checkpoint identities; select exact historical cuts and approved comparison scopes.
Compare legacy and V2 independently: P1.4 stored-window reconstruction remains distinct from factory-approved schedule policy. Preserve raw observations/contributions and legacy results.
Reproduce operands, receipts, missing-authority outcomes, witnesses and canonical results; verify exact replay and no cross-processor mutation.
Report which historical periods are calculable versus insufficient/corrupt. A successful replay with InsufficientEvidence can validate safety but cannot establish numeric business acceptance.
No production dashboard switch or server deployment follows automatically; those require separate acceptance and authorization.
