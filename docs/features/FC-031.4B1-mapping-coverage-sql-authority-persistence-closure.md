## Identity and materialization

The SQL store uses the frozen physical identity:

```text
MachineId
+
OrdinalStringKeyCodec(StreamKey)
+
StringOrderKeyV2Codec(MappingProcessorId.Value)
```

The caller-supplied `ObservationStreamId` and `ObservationProcessorId` remain semantic authority. The persisted processor text and V2 order key are validated for coherence during materialization; the stream key is not decoded to reconstruct caller identity.

`RawConsumedThrough`, nullable `MappedEvaluationInputHighWater`, and `MappingRevision` use the existing `SqlServerUInt64` representation. Persisted materialization explicitly rejects mapped high-water above raw consumed coverage.

Malformed persisted identity, order-key, numeric, position, revision, or cross-field state is classified as persisted corruption and surfaces as `InvalidOperationException`.

## Read authority

`ReadAsync` performs a point read over the physical Mapping identity and returns `null` when no row exists.

The read path performs no transaction, mutation lock, revision allocation, replay interpretation, or CAS behavior.

Cancellation is observed before SQL and propagated through connection, command, and reader operations.

## Commit / CAS authority

Mutation uses the frozen two-layer CAS protocol:

```text
Serializable transaction
        ↓
SELECT ... WITH (UPDLOCK, HOLDLOCK)
        ↓
materialize + validate current authority
        ↓
portable semantic CAS / replay decision
        ↓
INSERT
or
revision-guarded UPDATE
        ↓
affected rows == 1
        ↓
COMMIT
```

The store preserves the portable replay algebra:

```text
current == expected
  same coverage
    -> success / no mutation

  changed coverage
    -> publication

current != expected
  current present + same resulting coverage
    -> stale exact / lost-ack replay success / no mutation

  otherwise
    -> conflict
```

Initial publication allocates Mapping revision `0`. Changed publication from an existing authority advances the revision by exactly one. Changed coverage at `ulong.MaxValue` is rejected as revision-space exhaustion; exact replay remains non-mutating.

Failure and cancellation roll back with `CancellationToken.None` so rollback does not replace the original operation outcome.

```text

```

The existing Migration 008 CHECK constraints physically reject out-of-range UInt64 values, zero positive positions, and mapped high-water above raw coverage. The conformance slice does not disable those constraints merely to manufacture physically forbidden rows.

## Provider composition boundary

The full SQL regression exposed an existing provider-graph invariant:

```text
MappingCoverageAuthorityStore
        +
MachineStateActivityAuthorityStore
        ↓
must be supplied together
```

Therefore the concrete SQL Mapping store is implemented and directly conformant, but provider-level publication is intentionally deferred until the paired SQL state/activity authority store is available.

The final baseline-to-implementation delta contains no change to `SqlServerPersistenceServiceCollectionExtensions`.

This preserves the existing `ObservationAuthorityStoreGraph` invariant rather than weakening it or pulling SQL state/activity persistence into FC-031.4B.1.

Provider graph publication is therefore a composition dependency, not unfinished Mapping persistence.
