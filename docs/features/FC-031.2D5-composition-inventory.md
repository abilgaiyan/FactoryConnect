# FC-031.2D.5 — In-Memory Composition / Conformance Inventory

Status: CLOSED / FROZEN

## 1. Scope and authority boundary

FC-031.2D.5 defines the production in-memory composition cut for the already-frozen FC-031.2D state/activity continuity authority.

This record is documentation-only. It authorizes no production-code, test-code, SQL, API, dashboard, or later FC-031 implementation.

The inventory inherits the frozen FC-031.2D.1 through FC-031.2D.4 authority and the closed behavioral implementation. Those decisions MUST NOT be reopened unless concrete repository evidence demonstrates a contradiction.

The purpose of 2D.5 is narrowly:

```text
portable joint state/activity authority
    ↓
production in-memory composition
    ↓
sole mutation owner
    + mapped-input cursor authority
    + downstream activity-history authority
    + runtime recovery proof
```

## 2. Frozen production topology

The production topology for this slice is:

```text
InMemoryMachineStateActivityAuthorityStore
    ├── sole writer:
    │     JointAuthorityMachineStateActivityProcessor
    ├── cursor reader:
    │     joint Projection.Position
    └── activity-history reader:
          cumulative joint ActivityPeriodHistory
```

The same concrete joint-store instance is the underlying authority for all three consumers.

The following invariant governs the cutover:

```text
one lineage
one underlying joint authority state
one mutation owner
multiple read-only consumers
```

No processor, cursor reader, activity-history reader, lost-ack wrapper, test seam, adapter, or composition layer may create a second underlying state for the same joint lineage.

## 3. Sole mutation ownership

Production state/activity mutation SHALL be owned only by:

```text
JointAuthorityMachineStateActivityProcessor
    ↓
InMemoryMachineStateActivityAuthorityStore
```

The joint provider atomically owns:

```text
P = MachineStateActivityProjection
S = cumulative durable state-change history
A = cumulative durable activity-period history
E = EvaluationAuthority
```

The legacy `MachineStateActivityProcessor` and `InMemoryMachineStateActivityProjectionStore` may remain in the repository for direct component tests and historical FC-024 compatibility evidence, but they SHALL NOT remain a competing production mutation path for the joint lineage after the 2D.5 cutover.

An independently composed writable `IEvaluationAuthorityStore` over the same joint-owned lineage is likewise prohibited.

## 4. Mapped-runtime cursor authority

The production mapped-observation runtime cursor SHALL be the projection position from the same joint authority:

```text
mapped runtime cursor
    = joint MachineStateActivityProjection.Position
```

No new generic mapped-processing checkpoint is introduced.

The runtime read boundary remains exclusive:

```text
joint P.Position = N
    ↓
reader requests AfterPosition = N
    ↓
only positions > N are eligible
```

The raw FC-024 durable-processing checkpoint model remains unchanged.

## 5. Downstream activity-history authority

Production metric-input aggregation currently consumes machine activity through `IProductionContextActivityReader`.

After the 2D.5 cutover, production activity-period history SHALL be read from the cumulative activity history owned by the same `InMemoryMachineStateActivityAuthorityStore` instance that owns joint publication.

The governing semantic invariant is:

```text
activity-period history consumed downstream
    = activity-period history atomically published by the joint owner
```

The production implementation SHALL use a read-only adapter over the concrete joint in-memory store, or an equivalent read-only surface over that same state.

The adapter SHALL preserve the existing externally relevant reader behavior:

```text
stream filtering
strict afterPosition filtering
ascending durable Position ordering
batchSize limiting
argument validation
cancellation behavior
```

The legacy projection-backed production reader SHALL NOT remain the production activity-history authority after cutover.

No new portable activity-history storage abstraction is required by this slice.

## 6. Production continuity-policy authority

FC-031.2D.5 freezes one composition-owned immutable production continuity policy:

```text
Mode        Preserve
Identity    continuity/preserve
Version     1.0
Lifetime    singleton / application lifetime
Scope       all configured production machine-state-activity streams
```

Equivalent construction:

```text
CurrentStateContinuityPolicy(
    CurrentStatePolicyReference("continuity/preserve", "1.0"),
    StateContinuityMode.Preserve)
```

This policy is owned by production composition, not by mutable runtime input.

Every logical publication SHALL receive one stable policy instance, and:

```text
mode used by processor
    corresponds exactly to
EvaluationAuthority.AppliedContinuityPolicy
```

Therefore every production evaluation publication created under this slice records exactly:

```text
continuity/preserve @ 1.0
```

### Configuration decision

FC-031.2D.5 introduces no new required continuity configuration.

```text
policy source                    composition-owned canonical policy
missing configuration behavior   not applicable
invalid configuration behavior   not applicable
single-stream applicability      same Preserve policy

```

`Reset` remains a supported portable behavioral mode and remains valid for conformance tests, but production-selectable Reset configuration is outside 2D.5.

This Preserve default retains the effective continuity behavior of the legacy production state/activity processor while changing the authority/composition model.

## 7. Runtime recovery semantics

### 7.1 No newer mapped input

Normal in-memory restart/recovery is:

```text
joint authority committed through N
    ↓
fresh runtime reads joint P.Position = N
    ↓
mapped reader requests AfterPosition = N
    ↓
reader returns empty batch
    ↓
processor is not invoked
    ↓
PublishAsync is not called
    ↓
P/S/A/E remain unchanged
    ↓
ProjectionRevision remains unchanged
```

An empty read therefore causes no synthetic replay, no revision allocation, and no publication churn.

### 7.2 Newer mapped input exists

```text
joint authority committed through N
    ↓
fresh runtime reads joint P.Position = N
    ↓
mapped reader returns only positions > N
    ↓
joint processor restores coherent P+E
    ↓
only forward observations are evaluated
    ↓
one legitimate forward publication
    ↓
revision advances normally
```

### 7.3 Overlap classification

Full-overlap and partial-overlap handling remain inherited calculator/processor defensive conformance:

```text
full overlap
    → NoAdvance

partial overlap
    → committed prefix skipped
    → forward suffix only
```

Normal production in-memory cursor restoration does not intentionally manufacture overlap.

An overlap-injecting reader may be used as optional robustness evidence but is not required for the normal recovery proof.

## 8. Lost-acknowledgement proof discipline

Any test-only acknowledgement-loss wrapper or other recovery seam MUST delegate to the same underlying joint authority state used by:

```text
processor publication
runtime cursor restoration
activity-history reads
```

A test wrapper MAY suppress or transform acknowledgement visibility after the underlying joint commit, but MUST NOT maintain a parallel projection, authority record, cursor, activity history, or second joint-store instance for the tested lineage.

The distinction between provider replay and fresh runtime recovery remains frozen:

```text
retained identical proposal resubmission
    → provider ExactReplay classification

fresh runtime invocation after committed state
    → coherent reread
    → exclusive cursor restoration
    → empty batch or forward continuation
```

## 10. Conformance obligations

### A — Same-store ownership

Prove one concrete joint-store instance underlies:

```text
joint processor publication
mapped-runtime cursor reads
production activity-history reads
```

### B — Cursor correctness

Prove:

```text
runtime cursor = joint Snapshot.Projection.Position
reader continuation is strictly after that position
```

### C — Activity-history correctness

Prove the production activity reader returns the joint store's cumulative `ActivityPeriodHistory` and preserves:

```text
stream filtering
strict afterPosition
position ordering
batchSize
cancellation
argument validation
```

### D — Policy/composition correctness

Prove production composition uses one immutable singleton:

```text
continuity/preserve @ 1.0
StateContinuityMode.Preserve
```

and the exact reference is persisted as `EvaluationAuthority.AppliedContinuityPolicy`.

### E — Competing-writer exclusion

Prove production composition does not select:

```text
MachineStateActivityProcessor
    as the production joint-lineage writer

InMemoryMachineStateActivityProjectionStore
    as production mutation/cursor/activity-history authority

independent IEvaluationAuthorityStore publication
    over the joint-owned lineage
```

### F — Runtime recovery matrix

At minimum prove:

```text
F-01 fresh bootstrap publishes coherent P/S/A/E

F-02 restart restores cursor from joint P.Position
     and continues strictly after N

F-03 lost acknowledgement + no newer mapped input
     → empty read
     → no processor/publication call
     → no revision churn

F-04 lost acknowledgement + newer mapped input
     → committed prefix is not returned
     → only forward input is processed
     → one legitimate forward publication

F-05 restart retains LastConsumedInstanceId and Preserve
     context across an acquisition-instance boundary

F-06 resulting EvaluationAuthority records
     continuity/preserve @ 1.0 exactly
```

### G — Downstream compatibility

Prove the production path:

```text
joint activity publication
    ↓
production-context activity reader
    ↓
production-context processing
    ↓
metric-input aggregation
```

without requiring publication into the legacy projection-only activity store.

Compatibility evidence SHALL include the relevant:

```text
Edge observation-processing composition
Edge production-metric-input composition
production-context activity processing
production metric-input aggregation
SQL-backed production aggregation composition tests
existing FC-024 raw-processing tests
legacy processor direct component tests
multi-stream processing/composition tests
```
