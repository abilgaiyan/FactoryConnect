## 4. Lost-acknowledgement proof seam

The test-oriented lost-acknowledgement seam delegates every read and publication to the same joint authority store.

Its only special behavior is:

```text
inner PublishAsync returns accepted NewPublication
    ↓
wrapper throws LostAcknowledgementException once
```

The wrapper does not retain or reconstruct any parallel projection, evaluation authority, cursor, state-change history, or activity-period history.

Therefore ambiguous acknowledgement is modeled without introducing a second state owner.

No retry loop or automatic replay policy is introduced.

## 7. F-03 — Lost acknowledgement with no newer input

The proof commits a fresh joint publication and then deliberately loses its acknowledgement.

After restart:

```text
joint P.Position reflects the committed publication
    ↓
runtime requests mapped observations strictly after P.Position
    ↓
reader returns an empty batch
    ↓
processor is not invoked
    ↓
PublishAsync is not invoked again
    ↓
ProjectionRevision remains unchanged
```

This proves that a lost acknowledgement does not create revision churn when no newer mapped input exists.

Result:

```text
F-03  PROVEN
```

## 9. F-05 — Preserve continuity across restart and instance boundary
