## Semantic identity and compatibility

Reserved projection processor: `operational-metrics:{MachineId:D}:builtins-v2-planned-production-availability-v2`.
Reserved Availability definition: metric key `availability`, version `2`; result is a dimensionless ratio in [0,1], displayed as a percentage only at presentation.
These identities are design reservations, not registered executable capabilities.

| Operand | Meaning |
| --- | --- |
| TotalRunningDuration | Established Running duration in the exact reporting scope, independent of planned eligibility |
| EligibleRunningDuration | Established Running duration intersected with established planned-production intervals in the same scope and revision |
| PlannedOperatingTime | Duration of established planned-production intervals after approved exclusions |

All duration operands use seconds derived from integer UTC ticks; no floating-point TotalSeconds or intermediate rounding. Availability = EligibleRunningDuration / PlannedOperatingTime.
Legacy ActualProductionTime, builtins-v1 and availability-containment-v1 remain unchanged. Do not globally remap ActualProductionTime or change Performance/Utilization. ## Exact scope and evidence

Bind machine, stream, aggregation processor and exact committed revision position, full shift occurrence or production-day identity, context partition, policy, schedule assignment/version and exclusion policy. Never read newer contributions into an older result.
Intervals are half-open [start,end), UTC, positive-duration, clipped to the bound scope and split at shift/day, schedule, break and activity boundaries. Production-day intervals are unions of disjoint segments, not an envelope across gaps. Local schedule expansion is upstream and must bind timezone/version and DST handling.

Reconstruct from position-bounded immutable facts plus exact eligibility and contextualized activity references. Resolve references against the same historical authority. Validate duration/tick equality, ownership, unique fact IDs/positions, source interval identities, schedule assignment, exclusions and membership.
True eligibility requires a matching planned assignment and matching planned interval coverage; false requires established exclusion evidence and no planned assignment on that fact. Null, missing references, unknown state, conflicting assignments or contradictory inclusion/exclusion never mean false.

EligibleRunningDuration is the sum of disjoint running intersections with validated planned intervals. Retain exact participating fact IDs/positions, source references and clipped endpoints as operand provenance. Preserve excluded running separately as activity evidence; it does not trigger the legacy containment rule in this new policy. Do not derive the numerator by unproved subtraction.

A running fact crossing an eligibility boundary must be split using authoritative historical boundaries; its single boolean is insufficient to infer those boundaries. If that authority is unavailable, return InsufficientEvidence. Never manufacture a boundary from aggregate timestamps.

## Completeness and zero

Zero eligible running is calculable only with a durable, revision-bound coverage proof that the entire planned interval set has established activity classification and eligibility. No Running row is not proof of zero. Unknown/offline observations do not automatically prove non-running; activity authority must establish the classification.
A complete proof must identify its scope, source cut, covered interval set, gaps, continuity authority and schedule/exclusion versions. Existing aggregate InputCount/first/last timestamps and a caller-supplied boolean do not provide this proof.
P1.6C must specify and validate the concrete persisted proof representation before enabling V2. This document does not claim existing coverage contracts already satisfy it.
Partial observed periods may calculate only under a separately versioned as-of scope that bounds both operands and the completeness proof; do not compare partial running against an implicitly complete-day denominator.

| Condition | Semantic result / reason |
| --- | --- |
| Complete operands, planned > 0 | Calculated, eligible / planned, including exact zero |
| Complete schedule proves planned = 0 | Unavailable / NoPlannedProduction (not applicable); null value |
| Missing schedule, eligibility, coverage or required references | InsufficientEvidence / explicit MissingSchedule, MissingEligibility or IncompleteActivityCoverage |
| Contradictory eligibility or overlapping/duplicate contributions | Unavailable / ConflictingEligibility or InvalidIntervalEvidence; integrity failures may reject before evaluation |
| Eligible > planned, or negative operands | Unavailable / AvailabilityOperandInvariantViolation; no clamp |
| Exact source revision unavailable or corrupt durable proof | Reject read/publication with historical integrity error; do not publish a plausible number |

Reason names are semantic reservations; no enum additions in P1.6A/B. Zero denominator is not InsufficientEvidence when complete evidence proves no planned production. Validate contradictions before the zero-denominator branch.
Normalize transport duplicates only through existing idempotent identity handling before reconstruction. Duplicate entries inside an accepted reconstruction set and overlapping running intervals are rejected, never silently summed or deduplicated.
