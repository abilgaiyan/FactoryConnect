## 2. Frozen recovery-layer distinction

FC-031.2D.4C freezes two distinct recovery mechanisms:

```text
provider retained-proposal recovery
    versus
fresh processor/runtime recovery
```

`ExactReplay` remains a provider classification of a submitted complete proposal. It does not imply automatic retry, retry scheduling, retry ownership, processor-local retry policy, or processor integration.

Fresh recovery does not require retention or reconstruction of the previous complete proposal. It begins from a coherent P+E reread:

```text
fully covered input
    → NoAdvance

partially covered input
    → skip incorporated prefix
    → evaluate forward suffix
```

`NoAdvance` is a fresh-evaluation outcome, not a provider replay classification. Fresh end-to-end execution proof remains deferred until processor/joint-authority integration is separately authorized.

## 3. Frozen post-commit semantic cut

The lost-acknowledgement proof freezes only this semantic condition:

```text
joint provider commit has become authoritative
    ↓
caller has not observed successful acknowledgement
```

Equivalently:

```text

caller observed failure or ambiguity
```

No concrete proof mechanism is frozen.

An external test wrapper is a natural implementation candidate:

```text

    → call inner PublishAsync
    → inner returns NewPublication

```

but this is non-normative. A provider-local seam remains possible. The contract freezes the semantic cut, not its mechanism.

## 4. Frozen provider replay authority

The inherited publication ordering remains:

```text

```

Therefore:

```text
ExactReplay precedes CAS rejection
ExactReplay precedes revision exhaustion
```

Expected projection position and expected authority revision remain excluded from replay identity.

## 5. Frozen complete P/S/A/E replay oracle

The provider-level proof is evaluated over:

```text
P = MachineStateActivityProjection
S = durable state-change history
A = durable activity-period history
E = EvaluationAuthority
```

For every accepted replay:

```text
P unchanged
S history unchanged
A history unchanged
E unchanged
ProjectionRevision unchanged
```

Replay must not allocate a revision, append state/activity history, alter projection state, or alter EvaluationAuthority.

Complete replay identity remains the inherited canonical structural identity from FC-031.2D.3 / 4A. A changed payload cannot qualify as exact replay merely because expected tokens match.

## 6. Frozen C-01 through C-06 provider matrix

### C-01 — Fresh NewPublication acknowledgement lost

```text
fresh NewPublication commits
acknowledgement is lost
same retained proposal is resubmitted
    → Accepted / ExactReplay
```

Required: same P/S/A/E, same revision, no history duplication.

### C-02 — Forward NewPublication acknowledgement lost

```text
established lineage
forward NewPublication commits
acknowledgement is lost
same retained proposal is resubmitted
    → Accepted / ExactReplay
```

Required: same committed forward P/S/A/E, same committed revision, no history duplication.

### C-03 — Repeated retained-proposal replay

Repeated direct resubmission remains `Accepted / ExactReplay` with stable projection, authority, revision, state-change history, and activity-period history.

### C-04 — Exact replay at revision `ulong.MaxValue`

If current authority already carries `ProjectionRevision = ulong.MaxValue`, an exact retained replay remains `Accepted / ExactReplay`. No revision allocation occurs.

### C-05 — Same expected tokens, changed payload

Matching expected projection position and authority revision do not weaken complete-payload replay identity. Any changed complete payload is **not ExactReplay**. Its later classification remains governed by inherited algebra: contradictory or non-forward changed proposals conflict; a separately valid changed-forward proposal is not replay merely because expected tokens match.

### C-06 — Lineage isolation during lost-ack recovery

Recovery for one `(StateProcessorId, ObservationStreamId)` lineage must not mutate any other lineage. Processor/stream isolation remains part of the provider proof obligation.
