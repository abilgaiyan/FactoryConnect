# 1. Closure blockers found by the whole-system pass

## B1 — Nullable SQL CHECK predicates are not yet frozen as total predicates

The physical contract currently names period/context/status/evidence-shape checks semantically. SQL Server `CHECK` accepts `TRUE` **and `UNKNOWN`**, so nullable fields require explicit `IS NULL` / `IS NOT NULL` structure. Migration 005 must not translate implication-like prose directly into nullable expressions.

Required resolution: freeze the exact total predicates in section 3 of this matrix and use those exact definitions in migration 005 and `CurrentSchemaDescriptor`.

Classification: **SQL-authoritative** for mechanical nullable shape; semantic codec/domain validation remains reader-owned where stated.

## B2 — Evidence ordinal contiguity has no current enforcement owner

Current relational constraints prove only:

```text
EvidenceOrdinal >= 0
UNIQUE (ProjectionRowId, EvidenceKind, EvidenceOrdinal)
```

They do not prove that each kind reconstructs as exactly `0..count-1`. A row set `{0,2}` is mechanically legal but is not a valid projection of provider-neutral list order.

Required resolution:

- writer emits contiguous zero-based ordinals independently within each `EvidenceKind`;
- reader orders by `(EvidenceKind, EvidenceOrdinal)` and requires exact `0..N-1` with no gaps;
- gap/negative/duplicate cases have deterministic corruption diagnostics.

Classification: **Writer construction invariant + reader revalidation**.

## B3 — Roster occurrence complete identity exceeds the clustered-key safety envelope

The complete occurrence identity is:

```text
RosterRowId                         bigint
ShiftScheduleAssignmentId          nvarchar(256)
ShiftId                            nvarchar(256)
ShiftStartsAtUtc                   datetimeoffset(7)
ShiftEndsAtUtc                     datetimeoffset(7)
```

Worst-case encoded key width is greater than SQL Server's 900-byte clustered-index key limit. It is below the modern nonclustered key limit, but that must be proven against the supported real SQL Server target.

Required resolution: freeze the complete occurrence key as **PRIMARY KEY NONCLUSTERED** (or an equivalently explicit NONCLUSTERED UQ if a surrogate PK is later chosen). Migration 005 must not rely on the default PK backing-index type.

Classification: **SQL-authoritative**.

Required real-SQL proof: table/index creation at declared maximum widths, duplicate rejection, exact schema metadata, and startup descriptor compatibility.

## B4 — Projection processor duplicated representation lacks explicit mutual validation

`dbo.OperationalMetricProjectionProcessor` stores both:

```text
ProcessorKeyBinary
ProcessorKey
```

plus relational aggregation-processor/stream binding columns. The current contract does not explicitly assign mutual consistency between these duplicated representations.

Required resolution:

- writer constructs all representations from the same provider-neutral projection processor identity/binding;
- reader decodes/reconstructs the processor identity and validates `ProcessorKeyBinary`, `ProcessorKey`, `MetricAggregationProcessorRowId`, and `MetricInputStreamRowId` agree;
- mismatch is persisted-data corruption, never “processor not found”.

Classification: **Writer construction invariant + reader revalidation**.

# 3. Exact total SQL CHECK shapes required before physical freeze

These predicates are written so nullable fields never rely on SQL `UNKNOWN` as acceptance authority.

## 3.1 General nullable scalar outer checks

For an optional scalar `X`, outer range/domain checks use:

```sql
X IS NULL OR <valid-X-predicate>
```

Subtype/presence constraints separately determine when `X` MUST be NULL or MUST be NOT NULL.

Required examples:

```sql
ReasonCode IS NULL OR ReasonCode IN (0,1,2,3,4,5)
MetricDimension IS NULL OR MetricDimension IN (0,1,2)
InputCount IS NULL OR InputCount BETWEEN 1 AND 9223372036854775807
DependencySnapshotCodecVersion IS NULL OR DependencySnapshotCodecVersion = 1
DependencySnapshotBinary IS NULL OR DATALENGTH(DependencySnapshotBinary) BETWEEN 1 AND 16777216
FirstInputTimestamp IS NULL OR DATEPART(TZOFFSET, FirstInputTimestamp) = 0
LastInputTimestamp IS NULL OR DATEPART(TZOFFSET, LastInputTimestamp) = 0
```

## 3.2 Projection period union

Required total shape:

```sql
(
    PeriodKind = 1
    AND PeriodSiteId IS NOT NULL
    AND DATALENGTH(PeriodSiteId) > 0
    AND ShiftScheduleAssignmentId IS NOT NULL
    AND DATALENGTH(ShiftScheduleAssignmentId) > 0
```

# 4. Hash authority and collision policy

Hashes are **lookup accelerators and corruption detectors**, never canonical equality authority.

## Evaluation key

```text
lookup slot:
  ProjectionProcessorRowId + EvaluationKeyHash

identity decision:
  exact EvaluationKeyBinary ordinal equality

collision:
  same hash + different bytes => deterministic EvaluationKeyHashCollision
```

Writer behavior under the unique hash slot must distinguish:

```text
same hash + same bytes       -> same logical key/update path
same hash + different bytes  -> collision failure/no mutation
```

Reader always recomputes SHA-256 over exact complete bytes before parsing.

## Dependency snapshot

The stored dependency hash is not indexed as logical identity. It is a corruption detector:

```text
SHA-256(exact complete DependencySnapshotBinary)
== DependencySnapshotHash
```

Hash mismatch is reported before recursive parsing.

## Real SQL hash characterization

Before physical closure, real SQL Server conformance must prove `HASHBYTES('SHA2_256', @binary)` agrees with .NET SHA-256 for representative FCEK/FCDS vectors, including the largest supported SQL input used by any diagnostic/test path. This does **not** promote SQL `HASHBYTES` to canonical equality authority; it is target characterization evidence only unless migration 005 explicitly introduces a computed hash, which this contract currently does not.
