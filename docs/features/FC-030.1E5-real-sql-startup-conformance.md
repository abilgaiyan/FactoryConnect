## Goal

Prove the production SQL startup path against real SQL Server:

```text
startup gate
    -> C Exclusive migration/adoption
    -> D Shared compatibility verification
    -> Compatible only
    -> host activation permitted
```

## Determinism rule

Concurrency and timeout proofs use isolated databases, explicit SQL session ids, `sys.dm_tran_locks` observation, bounded setup/completion guards, incomplete-task assertions while blocked, deterministic transaction commit/rollback release, and primary-failure-preserving cleanup.

Elapsed time and `Task.Delay` are never authoritative evidence of lock ordering.

The E.5.3 and E.5.4 load-sensitive fixtures share a non-parallel xUnit collection. This removes unrelated SQL Server fixture load while preserving the actual concurrency internal to each proof.

## E.5.2 — Migration-stage failures

```text

```

Coverage includes ledger identity/shape/history defects, unledgered incompatible schema, identity/checksum mismatch, migration-lock timeout, and forced migration-003 failure with rollback/retry convergence.

## E.5.3 — Verification-stage outcomes

Real D coverage proves:

- structural drift -> exact `DatabaseIncompatible` result;
- Shared-lock timeout -> `VerificationOperationalFailure` with exact provider cause;
- provider `SqlException` cancellation while blocked in `sp_getapplock` remains an operational failure;
- any actual `OperationCanceledException` emitted by the stage propagates unchanged;
- activation remains zero for every rejection.

The authoritative lock/observation semantics remain short and deterministic; outer completion guards exist only as deadlock protection and do not define SQL behavior.

## E.5.4 — Concurrent SQL startup

Three real-SQL tests prove:

```text
empty database + API/Edge-labelled concurrent startup
prefix-002 API first / Edge waits
prefix-002 Edge first / API waits
```

SQL metadata proves transaction-owned `APPLICATION` lock state, including winner `GRANT/X` and waiter `WAIT/X` where applicable. Final history is canonical 001–004 exactly once, Current schema is exact, both gates verify `Compatible`, and both activate once.

Frozen E.5.4 bounds:

```text
startup C/D lock timeout    2 minutes
completion deadlock guard   2 minutes
SQL lock observation        10 seconds
```

Focused concurrency was stable across repeated runs and the fixture is isolated from unrelated SQL test scheduling.

## E.5.5 — Commit-boundary proof

An exact-current database is transactionally changed while an external transaction owns the Exclusive migration applock. Startup C is observed `WAIT/X`; activation and D remain zero. After the external transaction commits the structural drift, C re-reads committed state and owns the rejection through `FinalSchemaValidationException`, translated to `MigrationOperationalFailure`.

A separate read-only D call classifies the committed state as `MigrationSchemaDrift`, confirming the database state without changing frozen C-before-D startup precedence.

Focused real-SQL result: **1/1 PASS**.
