# 4. Replacement-direction constraint

Any replacement SQL comparison representation must preserve exact `.NET StringComparer.Ordinal` semantics.

Because `StringComparer.Ordinal` compares UTF-16 code units ordinally, a candidate replacement may use a bounded deterministic binary key derived from the exact UTF-16 code-unit sequence. With the frozen `CanonicalStringV1` maximum of 256 UTF-16 code units, such a key can be bounded to at most 512 payload bytes before any optional framing.

That is a **candidate direction only**, not yet frozen authority. It requires independent real-SQL proof for:

```text
exact equality parity
exact ordering parity
prefix behavior
trailing U+0020
embedded/trailing U+0000
BMP/supplementary boundaries
maximum-length values
ORDER BY
startAfter seek
filters
PK/UQ uniqueness
all affected key-width/index limits
writer construction + reader revalidation if stored rather than computed
```

If a replacement representation changes the physical columns/indexes, the seven-table matrix, key-width review, object-name freeze, and CurrentSchemaDescriptor candidate must be updated before FC-030.2A can close.
