# 1. Comparison rule

Provider-neutral string identity/order authority is:

```text
StringComparer.Ordinal
```

Raw SQL `nvarchar` comparison is not semantic authority.

Whenever SQL equality/order has semantic effect before reader reconstruction, the row persists both:

```text
Value      nvarchar(...)
OrderKey   varbinary(769)
```

where `OrderKey = StringOrderKeyV2(Value)`.

`StringOrderKeyV2` is writer-constructed and reader-revalidated. SQL owns only outer nullability/length and the relational comparison over the binary key. Any text/key mismatch is persisted-data corruption.

Storage-only strings retain their `nvarchar` value without an order-key companion. They are validated/reconstructed by the reader and MUST NOT be used as provider-neutral SQL equality/order authority later without a new architecture review.

```text

  -> ProcessorKeyBinary only
```

`ProcessorKeyBinary` is not the rejected raw-UTF-16 `StringOrderKeyV1` representation. It uses the same V2 encoding proven for every other SQL-semantic ordinal string comparison.

B4 ownership is therefore:

```text

  validate ProcessorKey through CanonicalStringV1
  encode ProcessorKeyBinary using StringOrderKeyV2
  persist aggregation/stream binding coherently

SQL:
  UQ ProcessorKeyBinary
  lookup and CAS locking use ProcessorKeyBinary

reader:
  validate ProcessorKey
  re-encode using StringOrderKeyV2
  require exact ProcessorKeyBinary equality
  validate aggregation/stream binding

mismatch:
  deterministic persisted-data corruption
```

# 4. Required V2 outer SQL shape

Required/non-empty semantic string:

```sql
Value IS NOT NULL
AND DATALENGTH(Value) > 0
AND OrderKey IS NOT NULL
AND DATALENGTH(OrderKey) BETWEEN 1 AND 769
```

Optional context string:

```sql
(
    Present = 0
    AND Value IS NULL
    AND OrderKey IS NULL
)
OR
(
    Present = 1
    AND Value IS NOT NULL
    AND DATALENGTH(Value) > 0
    AND OrderKey IS NOT NULL
    AND DATALENGTH(OrderKey) BETWEEN 1 AND 769
)
```

Processor identity outer shape:

```sql
ProcessorKey IS NOT NULL
AND DATALENGTH(ProcessorKey) > 0
AND ProcessorKeyBinary IS NOT NULL
AND DATALENGTH(ProcessorKeyBinary) BETWEEN 1 AND 769
```

SQL does not prove `OrderKey = StringOrderKeyV2(Value)` or `ProcessorKeyBinary = StringOrderKeyV2(ProcessorKey)`. Those mutual semantic invariants are:

```text
Writer construction invariant + reader revalidation
```

The reader must re-encode the exact reconstructed .NET string and require byte-for-byte equality with the persisted key before the row is accepted.
