## Scope closed

This slice establishes provider ownership and identity for the in-memory current-state authority graph without activating current-state authority reading and without constructing the authority-cut provider.

The selected InMemory persistence provider owns exactly one instance each of:

```text
InMemoryObservationIngestionStore
InMemoryMappingCoverageAuthorityStore
InMemoryMachineStateActivityAuthorityStore
```

`PersistenceProviderServices` carries the mapping and state/activity stores through abstraction-typed optional internal dependency roles. Persistence finalization projects those exact instances into DI. The internal roles remain outside the persistence capability mask, activated-capability collision detection, and individual-capability validation.

`PersistenceProviderCapabilities.All` remains unchanged, and the InMemory provider does not advertise `CurrentStateAuthorityReading` in this slice.

Repeated DI resolution preserves the selected-provider singleton lifetime.

## Binding isolation proof

Multiple current-state bindings use the same provider-owned mapping and state/activity store instances while authority state remains isolated by the existing store keys:

```text

(mappingProcessorId, observationStreamId)

(stateProcessorId, observationStreamId)
```

No authority state leaks between bindings that share processor identities but use different observation streams.

## Provider compatibility proof

The SQL provider remains source- and behavior-compatible with the optional internal roles:

```text
MappingCoverageAuthorityStore         null

CurrentStateAuthorityCutProvider      null
```

Its capability declaration is unchanged and does not include `CurrentStateAuthorityReading`.

Legacy/provider construction using the pre-existing required `PersistenceProviderServices` constructor arguments remains valid. Existing activated persistence capabilities continue to resolve normally when the optional internal roles are absent.

## Transitional composition condition

The frozen FC-031.2D observation composition may still replace those finalized registrations during the transition. That behavior is intentionally deferred to later handoff work.

Therefore FC-031.2E.A closes only the provider-owned instance graph and finalized persistence identity boundary.
