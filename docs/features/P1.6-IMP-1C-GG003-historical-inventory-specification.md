## Purpose and authorization

Specify the smallest read-only investigation that can distinguish retained SQL evidence from missing historical authority and unexamined external artifacts.
This PR contains no SQL script, database connection, restore operation, replay, backfill, migration or runtime implementation.
Future execution requires an explicitly identified disposable GG-003 restore and authorized read-only scope. The production server/database is not an inventory target.
Restoring a backup and running any potentially writing provider API require separate review; the inventory must not invoke Publish/Commit, processing workers, startup migration or DI boot paths that mutate state.
Use least-privilege read access. SELECT-only intent is insufficient if a tool invokes mutating initialization.

## Target and reproducibility envelope

Before any query, identify:
- Inventory run ID, UTC capture time, investigator/tool version and this specification commit.
- Disposable host/instance/database identity, restore provenance, backup identity/hash if available, backup/restore cutoff and schema migration history. Unknown backup identity is an explicit limitation.
- Machine GUID `677b030b-1ede-4a67-82ae-6a494791357f`, exact stream and processor identities verified from retained rows; display label GG-003 is not a database key.
- Exact aggregation processor/stream/revision for each requested scope; observation/metric-input/publication revision domains remain distinct.
- Fixed historical period identities, timezone evidence and requested scope boundaries. Capture UTC instants losslessly; IST is presentation only.
- Read consistency method. Prefer an immutable/quiescent disposable copy; if not, use an explicitly reviewed coherent read transaction. Do not change database isolation settings or claim separate unconstrained reads form one coherent snapshot.

Initial candidate scopes: production dates 16-19 October 2026 and their exact stored shift occurrences, with revision 534 as a known RCA candidate only if it exists under the verified processor/stream. Enumerate committed revisions affecting those scopes; retain the exact selection list and rationale.
Do not silently substitute latest revision, another processor or another restore when a requested target is absent. Per-revision evidence is reported separately; unioning facts from several cuts cannot complete one cut.

## I1 — Incorporated facts at exact revision

For each selected cut, identify all incorporated contribution rows and their exact fact/stream/position join. Record selected shift/day membership, metric keys, IDs, endpoints, exact persisted values/units, source IDs, eligibility and schedule references.
Validate unique positions/IDs, ownership, non-null required joins and source-cut bounds. Retain counts by key, resolved/unresolved reference counts and ordered evidence identifiers.
Keep the complete relevant membership inventory, not just a sample of running rows. Bounded samples illustrate findings but cannot prove absence, closure or completeness.
Do not calculate or publish V2 Availability. Observed arithmetic may be recorded as diagnostic evidence only, not an admitted result.

## I2/I3 — Payload resolution and closure

Resolve source IDs independently to exact eligibility/context payloads. Verify stored identity bytes, payload/hash and deserialized identity/ownership/time/state fields against the deployed encoding rules.
Compare source endpoints with facts using exact ticks and canonical values; record mismatches without rounding or repair. Legacy derivation/serialization behavior must be identified before interpreting a mismatch.
Resolve contextualized source references to joint activity history processor/stream/revision/ordinal and observation identity. Matching timestamps are not unique identity.

Apply IMP-1B closure requirements as a verification checklist:
- Enumerate each producer output's required fact membership and dependency set from retained authority, not from an invented reconstruction.
- An aggregation cut can admit only its exact verified subset; one incorporated fact cannot admit an entire producer batch.
- Output-only evidence requires explicit historical admission or independently verified equivalent bound to that cut.
- If no retained declaration establishes the dependency set, classify closure NotEstablished; do not synthesize a ProducerPublicationManifest and label it historical.
- A scheduled-duration fact can point to Unknown activity. Resolve state/continuity evidence; no running row is not proof of non-running.

## I4 — Schedule and external artifact boundary

Inventory SQL-retained historical schedule selection first. Separately list any candidate configuration backups, release manifests, deployment records, operator approvals, schedule exports and timezone/expansion versions available for inspection.
For each external artifact record identity/path, acquisition provenance, original content hash, exact version/effective scope, relationship to deployed producer and whether independent binding is established.
Export only the relevant sanitized selection and provenance references. Keep secrets/connection strings out of evidence; retain original hash privately where authorized, and give sanitized derivatives their own hashes.
File modification time, current config equality, assignment name POT-1 and reconstructed 11:30-19:30 IST windows do not by themselves prove historical authority.
Approved empty schedule requires positive complete selection/no-production evidence. No rows or absent configuration is not an approved empty schedule.
Factory approval of schedule/breaks remains distinct from faithful reconstruction of what configuration the software used.

## I5/I6/I7 — Classification, completion and retention

For each planned span with authoritative schedule, resolve Running/non-running/Unknown classification and bound policy versions, including mapping/source-instance changes and acquisition discontinuities.
Retain source-backed opening/closing/completion evidence. A still-open state cannot be closed at the requested period end by wall clock.
Inventory acquisition publication identity/ordinal/predecessors, opening boundary and raw accepted references. Record whether independent verification needs a prefix beyond the requested period.
If a full dependency prefix is required, record its bounded identifiers/counts and unresolved extent; do not silently truncate and mark verified. Request a separately reviewed larger read scope if needed.
Exact coverage assessment reads bind subject/revision and verify canonical content; then independently resolve schedule/evidence references. Current head, constructor validity and Complete classification alone are insufficient.
Record lost dependencies as integrity concerns. Archive equivalence requires independently verifiable retained payloads/provenance, not a promise that backups might exist.
Unknown schedule prevents complete planned-coverage reconciliation; it does not justify substituting activity-derived POT as full schedule authority.

## Evidence register and classifications

Each register entry includes category, exact subject/cut/scope, source location and typed identity/revision, validation performed, consistency capture, dependency IDs, result, affected interval set, limitation and next required evidence.
Store inventory observations separately from source authority. Capturing an ID/hash today proves what was inspected today, not that a missing historical receipt existed at the old cut.

| State | Required basis |
| --- | --- |
| AvailableAndVerifiable | Exact retained payload and authority/dependency chain independently verified for the requested cut |
| AbsentAtHistoricalCut | Positive complete historical selection/record establishes authority was not present/admitted at that cut |
| RetainedReferencePayloadMissing | Exact retained reference exists, but required payload cannot be resolved within established retained sources |
| Conflicting | Retained payload/identity/membership/authority contradicts another required retained fact |
| NotEstablished | Uninspected, inaccessible, incomplete search, unknown selection closure or unverified provenance |

A current empty query normally supports NotEstablished, not AbsentAtHistoricalCut. State the stores/artifacts searched when reporting a missing referenced payload; do not claim universal absence.
Multiple states may apply to different dependencies/spans. Preserve them per entry; do not flatten one verified subset into whole-day AvailableAndVerifiable.

## Deliverable and acceptance criteria

Future execution produces a reproducibility envelope, exact-cut selection list, complete relevant dependency register/counts, bounded sanitized evidence excerpts, artifact inventory, unresolved intervals and a reviewed feasibility decision.
Acceptance requires:
1. Every requested cut and scope is identified or explicitly unresolved; no latest-cut substitution.
2. Incorporated facts and output references reconcile, or mismatches/missing payloads are classified.
3. Producer subset/output-only closure is verified or explicitly NotEstablished.
4. SQL-derived windows are separated from immutable historical schedule selection and factory policy approval.
5. State/continuity/completion and acquisition/raw dependencies are independently traced with opening/gap limits.
6. Exact coverage references are checked beyond structural labels.
7. All missing/conflicting/unexamined authority remains explicit; no inferred zero or V2 numeric result.
8. Read-only execution evidence and target identity confirm no source mutation, replay or production access.
9. A reviewer assesses historical numeric support per cut; no success claim based solely on a runnable query/report.

Formal decision: HistoricalNumericSupported only for scopes whose required authority all verifies; ProspectiveOnly only after historical limitations and prospective producer capability are established; BlockedPendingAuthorityProducers when required producer facilities remain unavailable. Otherwise NotEstablished remains the decision.
Partial historical support must list exact supported and unsupported scopes. A valid InsufficientEvidence reconstruction is safety evidence, not numeric feasibility.
