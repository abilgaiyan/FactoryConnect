## 1. Purpose

This record freezes the bounded behavioral architecture that follows the completed FC-031.2D.4C lost-acknowledgement provider proof.

It defines the next implementation boundary without authorizing implementation. The boundary deliberately separates calculation-level state/activity continuity from the later production processor/runtime and dependency-injection cutover.

No frozen FC-031.2D authority is reopened by this record.

## 2. Frozen decomposition

The next implementation is an **uncomposed behavioral component**.

Its semantic boundary is:

```text
Inputs
    coherent MachineStateActivityAuthoritySnapshot?
    ordered durable mapped observations
    one CurrentStateContinuityPolicy

Outputs
    NoAdvance
    or deterministic MachineStateActivityAuthorityPublication
```

The exact production type name and internal factoring are implementation-local and are not frozen here.

An optional uncomposed processor variant may exercise `IMachineStateActivityAuthorityStore.PublishAsync(...)` to prove provider-result mapping. Such a variant must not be registered, substituted into the Edge production graph, or otherwise become the composed mutation path in this slice.

## 3. Why production cutover is deferred

The currently composed processor/runtime path is still projection-store based. Replacing its constructor dependencies with `IMachineStateActivityAuthorityStore` would require corresponding Edge construction changes and would compose the currently uncomposed joint provider.

That is a composition cutover, not merely a behavioral calculation change.

Therefore this inventory freezes the following split:

```text
behavioral slice
    uncomposed calculation and optional uncomposed provider-result adapter

FC-031.2D.5
    production processor/runtime cutover
    runtime cursor cutover
    Edge construction / DI composition
    sole mutation-owner composition proof
```

The behavioral slice must not leave a newly introduced production joint path alongside the existing independently writable projection-only path.

## 4. Coherent authority input

The behavioral calculation accepts either:

```text
null
```

for a fresh lineage, or one coherent:

```text
MachineStateActivityAuthoritySnapshot
    Projection
    EvaluationAuthority
```

for an established lineage.

For an established snapshot, evaluator working state is restored from the projection while FC-031 continuity identity and policy/revision authority come from `EvaluationAuthority`.

The inherited coherence is:

```text
Projection.ProcessorId == EvaluationAuthority.StateProcessorId
Projection.StreamId == EvaluationAuthority.ObservationStreamId
Projection.Position == EvaluationAuthority.EvaluatedThrough
Projection.State == EvaluationAuthority.MachineState
```

No legacy standalone projection may be adopted when a coherent joint snapshot is absent.

## 5. Fresh bootstrap

For a fresh lineage:

```text
working signals       = empty
working state         = Unknown
working ActiveState   = null
working ActiveStarted = null
previous InstanceId   = absent
expected P position   = null
expected E revision   = null
```

If no supplied mapped observation advances the lineage, the result is `NoAdvance`.

If observations are incorporated, the component produces the deterministic material for the first joint publication. Provider revision allocation remains provider-owned.

## 6. Established restoration

For an established lineage:

```text
working signals       <- Projection.Signals
working state         <- Projection.State
working ActiveState   <- Projection.ActiveState
working ActiveStarted <- Projection.ActiveStartedAt

previous InstanceId   <- EvaluationAuthority.LastConsumedInstanceId
expected P position   <- Projection.Position
expected E revision   <- EvaluationAuthority.ProjectionRevision
```

The starting projection position and authority revision are proposal expectations. They are not part of complete-payload replay identity.

## 7. Ordered input and incorporated-position rule

Mapped observations are processed in durable position order.

Any candidate whose durable position is less than or equal to the starting authoritative position is already incorporated and is skipped before continuity calculation.

Skipped observations:

```text
do not alter signals
do not alter state/activity context
do not alter LastConsumedInstanceId
do not emit outputs
do not create publication work
```

The continuity comparison for the first forward observation is therefore against the starting `EvaluationAuthority.LastConsumedInstanceId`, never against the instance identifier of an overlapping skipped candidate.

## 8. Full-overlap NoAdvance

If every supplied candidate is already incorporated:

```text
result = NoAdvance
```

`NoAdvance` means:

```text
no continuity transition calculation
no signal evaluation
no state-change output
no activity-period output
no joint publication proposal
no authority revision allocation
no mutation
```

`NoAdvance` is a behavioral outcome. This inventory does not require a new public provider result or public runtime result type merely to represent it.

## 9. Partial-overlap behavior

For an established authority through position `20` and candidates:

```text
19, 20, 21, 22
```

the calculation is:

```text
19  skip
20  skip
21  first forward observation
22  forward observation
```

Observation `21` compares its `InstanceId` with the starting `EvaluationAuthority.LastConsumedInstanceId`. Observation `22` compares with the rolling instance identifier established by observation `21`.

Only the forward suffix contributes to the new publication proposal.

## 10. Frozen Preserve / Reset calculation

The continuity boundary is evaluated before applying each newly incorporated observation.

### 10.1 Same instance

If the incoming `InstanceId` equals the last consumed instance identifier, evaluator context is retained and ordinary FC-024 evaluation continues.

### 10.2 New instance + Preserve

On an instance change under `Preserve`:

```text
Signals           preserved
State             preserved
ActiveState       preserved
ActiveStartedAt   preserved
```

The instance boundary itself emits no state transition and closes no activity period. The incoming mapped signal is then applied and ordinary evaluation proceeds.

### 10.3 New instance + Reset

On an instance change under `Reset`, before applying the first observation from the new instance:

```text
Signals           = empty
State             = Unknown
ActiveState       = null
ActiveStartedAt   = null
```

The reset boundary itself must not:

```text
emit old-state -> Unknown
close the previous activity period
use the first new-instance timestamp to terminate old activity
```

The incoming mapped signal is then applied and evaluated.

If the resulting state remains `Unknown`, no transition is emitted and `ActiveState` remains null.

If the resulting state is non-`Unknown`, the ordinary evaluation result is an `Unknown -> evaluated state` transition, with the new activity starting at the current observation timestamp.

### 10.4 Multiple boundaries

The policy is applied independently at every newly incorporated instance boundary, including multiple instance changes within one supplied batch.

The rolling last-consumed instance identifier is updated only after a forward observation is incorporated.

## 11. Policy stability and attribution

One `CurrentStateContinuityPolicy` governs one logical calculation/publication.

The continuity mode used by the calculation and the policy reference persisted into the resulting evaluation identity must describe the same policy choice.

The final proposal must therefore satisfy:

```text
EvaluationIdentity.AppliedContinuityPolicy
    = policy reference used by the calculation
```

The policy must not change midway through one logical publication calculation.

## 12. Deterministic joint publication output

When at least one forward observation is incorporated, the component produces deterministic material equivalent to a `MachineStateActivityAuthorityPublication` containing:

```text
ExpectedProjectionPosition
ExpectedAuthorityRevision
final MachineStateActivityProjection
ordered state-change publication delta
ordered activity-period publication delta
EvaluationAuthorityReplayIdentity
```

For an established lineage:

```text
ExpectedProjectionPosition = starting Projection.Position
ExpectedAuthorityRevision  = starting EvaluationAuthority.ProjectionRevision
```

For a fresh lineage both expectations are null.

The final evaluation identity must satisfy:

```text
EvaluatedThrough
    = final incorporated durable position

MachineState
    = final Projection.State

LastConsumedInstanceId
    = InstanceId at EvaluatedThrough

AppliedContinuityPolicy
    = policy reference used by this calculation
```

Provider-assigned `StateProjectionAuthorityRevision` is not calculated by the behavioral component.

## 13. Provider-result mapping

An optional uncomposed processor/provider adapter may prove the mapping from joint-provider results to `ProcessAsync` completion.

Required behavior:

```text
Accepted / NewPublication
    -> ProcessAsync succeeds

Accepted / ExactReplay
    -> ProcessAsync succeeds

Conflict
    -> ProcessAsync fails

RevisionExhausted
    -> ProcessAsync fails

NoAdvance
    -> no PublishAsync call
    -> ProcessAsync succeeds
```

`Conflict` and `RevisionExhausted` must not be swallowed or converted to success.

This slice must not introduce automatic reread, automatic recalculation, or automatic retry after either result.

The exact exception types used to make `ProcessAsync` fail are implementation-local and are not frozen by this inventory.

## 14. Batch-partition semantic convergence

For a fixed initial coherent authority state, one fixed continuity policy, and the same ordered mapped observations, changing only batch partitioning must preserve semantic evaluation convergence.

The required equivalent final semantics are:

```text
Projection.Signals
Projection.State
Projection.ActiveState
Projection.ActiveStartedAt

EvaluationAuthority.EvaluatedThrough
EvaluationAuthority.MachineState
EvaluationAuthority.LastConsumedInstanceId
EvaluationAuthority.AppliedContinuityPolicy

cumulative ordered state-change history
cumulative ordered activity-period history
```

The invariant explicitly excludes:

```text
StateProjectionAuthorityRevision
per-publication state-change delta grouping
per-publication activity-period delta grouping
```

Provider revision is publication-count dependent. For example, from revision `R`, one accepted publication can produce `R + 1`, while two accepted publications can produce `R + 2` even when both paths converge semantically.

Per-publication output-delta grouping is likewise publication-boundary dependent.

Revision and delta-grouping equality may be asserted only when publication boundaries themselves are held constant.

## 15. Fresh recovery wording discipline

The recovery responsibilities remain deliberately split.

```text

    proves calculation-level fresh recovery

FC-031.2D.5
    proves production runtime recovery and cursor cutover
```

Calculation-level fresh recovery includes:

```text

    -> NoAdvance

coherent P+E through position N
+ overlapping prefix followed by forward suffix
    -> skip prefix
    -> compare first forward InstanceId with E.LastConsumedInstanceId

```

A fresh invocation must not reconstruct the previously committed complete proposal merely to force provider `ExactReplay`.

Provider retained-proposal `ExactReplay` remains the distinct FC-031.2D.4C mechanism for a caller that actually retains and resubmits the exact deterministic proposal.

## 16. Runtime cursor authority

The semantic runtime rule remains:

```text
mapped runtime cursor
    = authoritative joint Projection.Position
```

No new generic mapped-processing checkpoint is authorized or required.

However, the currently composed runtime still obtains its cursor through the existing projection-only store. Executing the joint-authority cursor rule in production is therefore deferred to FC-031.2D.5.

FC-031.2D.5 must move the production runtime cursor to the joint authority's projection position, either by direct coherent joint read or an equivalent read-only projection over the same underlying authority.

The exact direct-read-versus-read-only-adapter mechanism is not frozen here.
