# FC-030.1D — Runtime Schema Compatibility Verification

## Status

**CLOSED / FROZEN.** D.1 through D.5 are complete. This document records the frozen runtime-compatibility boundary consumed by FC-030.1E.

## Runtime compatibility invariant

A runtime compatibility decision is computed from migration history and live FactoryConnect-owned schema observed while holding a Shared transaction-owned `FactoryConnect.SqlMigration` application lock. Runtime verification never adopts, migrates, repairs, or otherwise mutates persistent SQL Server state.

## Frozen classifications

```text
Compatible
DatabaseUninitialized
LegacyAdoptionRequired
UnledgeredSchemaIncompatible
MigrationPending
DatabaseNewerThanSupported
MigrationIdentityMismatch
MigrationChecksumMismatch
MigrationHistoryInvalid
MigrationLedgerSchemaInvalid
MigrationSchemaDrift
```

`MigrationHistoryInvalid` is reserved for malformed ledger row semantics such as non-canonical checksum representation or non-zero `AppliedAtUtc` offset. A syntactically canonical checksum that differs from repository authority is `MigrationChecksumMismatch`.

History mapping remains:

```text
ExactPrefixPending         -> MigrationPending
DatabaseNewerThanSupported -> DatabaseNewerThanSupported
IdentityMismatch           -> MigrationIdentityMismatch
ChecksumMismatch           -> MigrationChecksumMismatch
RowSemanticsInvalid        -> MigrationHistoryInvalid
ExactCurrent               -> continue to Current schema comparison
```

`ExactCurrent` is never sufficient by itself to return `Compatible`.

## Frozen D.3 verification flow

```text
open runtime connection
-> begin Serializable verification transaction
-> acquire Shared transaction-owned FactoryConnect.SqlMigration applock
-> resolve exact ledger identity and physical shape
-> read raw ledger rows without semantic validation
-> classify row semantics and history/catalog relationship
-> if history classification is terminal, return that runtime classification
-> otherwise compare live FactoryConnect-owned schema to CurrentSchemaDescriptor
-> exact schema -> Compatible
-> unequal schema -> MigrationSchemaDrift
-> rollback/dispose verification transaction
```

The Shared lock reuses the C lock authority:

```text
resource        FactoryConnect.SqlMigration
owner           Transaction
principal       public
mode            Shared
isolation       Serializable
lock timeout    SqlMigrationLockTimeout.ToMilliseconds
```

Negative `sp_getapplock` returns remain operational `SqlMigrationLockAcquisitionException`s, not compatibility results. Provider/read/connection/cancellation failures remain operational exceptions. Cleanup is best-effort and cannot replace the primary failure.

## Frozen future-history rules

A future suffix is `DatabaseNewerThanSupported` only when the entire supported prefix matches exactly and future rows remain canonically valid, strictly increasing by id, uniquely named, and compliant with the frozen migration-name grammar. Row-semantic invalidity and identity defects retain their frozen precedence.

## Frozen deterministic diagnostics

`SqlRuntimeCompatibilityResult` contains:

```text
Classification
Diagnostics[]
```

The diagnostic contract is frozen:

- `Compatible` has no diagnostics.
- Every non-compatible result has deterministic non-empty diagnostics.
- Operational failures never become diagnostics.
- Ordering is deterministic and independent of SQL metadata row order.
- Repeated verification of unchanged state returns value-equal diagnostics in the same order.
- No volatile timestamps, session ids, or provider exception messages participate.
- History diagnostics explain the already-selected classification rather than reclassifying it.
- `MigrationSchemaDrift` projects the existing `SqlSchemaComparator` differences against `CurrentSchemaDescriptor`.
- `UnledgeredSchemaIncompatible` projects differences against `LegacyPost004SchemaDescriptor`.
- D introduces no second structural comparator.

## D.5 real-SQL closure authority

D.5 proves the complete compatibility matrix against real SQL Server, including classification, deterministic diagnostics, Shared-lock behavior, repeatability, persistent-state non-mutation, and unrelated-object preservation.

The reusable `SqlRuntimeCompatibilityPersistentStateSnapshot` captures:

```text
ledger identity and physical structure
ledger rows
FactoryConnect-owned schema
unrelated sentinel object/value
```

and is reused by FC-030.1E rejection-containment proofs.

## Hard boundary

FC-030.1D must not:

- change C migration or ledger semantics;
- create or alter migration history;
- execute or adopt migrations;
- repair incompatible schema;
- change the frozen classification or diagnostic precedence;
- introduce migration 005;
- introduce production-reporting SQL persistence; or
- activate hosts.

FC-030.1E may only consume this verifier and sequence its result into the startup lifecycle.
