## Closed scope

FC-031.2E.C activates the already-existing portable current-state authority-reading capability for the InMemory persistence provider.

The production change is intentionally limited to the InMemory provider capability declaration:

```csharp
PersistenceProviderCapabilities.All |
PersistenceProviderCapabilities.CurrentStateAuthorityReading
```

No public contract, persistence finalizer, SQL provider, stable-cut provider, observation composition, or production composition behavior is changed by this slice.

## Capability vocabulary authority

`PersistenceProviderCapabilities.CurrentStateAuthorityReading` already existed before this slice.

The legacy aggregate meanings remain unchanged:

```text
Core & CurrentStateAuthorityReading == None
All  & CurrentStateAuthorityReading == None
```

FC-031.2E.C therefore does not redefine `Core` or `All`. Capability activation is explicit and provider-specific.

## InMemory provider declaration

The InMemory persistence provider now explicitly declares:

```text
PersistenceProviderCapabilities.All
| PersistenceProviderCapabilities.CurrentStateAuthorityReading
```

The provider-owned `InMemoryCurrentStateAuthorityCutProvider` and its authority instance graph were established by FC-031.2E.A and FC-031.2E.B. This slice only makes that existing provider capability selectable through persistence finalization.

No second current-state authority provider is created by finalized DI exposure.

## Non-requested behavior proof

When `CurrentStateAuthorityReading` is not requested, the InMemory provider may internally own its current-state authority-cut provider, but finalized persistence DI does not expose `ICurrentStateAuthorityCutProvider`.

This preserves the existing rule that optional provider capabilities are activated only when explicitly requested.

## Collision ownership proof

`ICurrentStateAuthorityCutProvider` is already part of the persistence finalizer's activated-capability collision set.

A pre-existing registration of `ICurrentStateAuthorityCutProvider` therefore causes persistence finalization to fail before selected-provider activation.

The ownership rule remains:

```text
Persistence activation owns activated capability interfaces.
```

No new collision mechanism was introduced by this slice.

## Unsupported-provider proof

The SQL persistence provider remains capability-incomplete for current-state authority reading.

When SQL is selected and `CurrentStateAuthorityReading` is requested:

```text
required-capability validation
    -> detects missing CurrentStateAuthorityReading
    -> rejects persistence finalization
    -> names CurrentStateAuthorityReading in the failure
```

The rejection occurs before lazy SQL provider-service/configuration construction. The conformance proof intentionally supplies no SQL connection string, demonstrating that capability validation fails first rather than later during SQL construction.

## SQL compatibility proof

The SQL production registration is unchanged.

Without the new current-state requirement:

```text
SQL persistence finalization               remains valid
SQL capability declaration                 remains unchanged
ICurrentStateAuthorityCutProvider          is not exposed
```

FC-031.2E.C adds no SQL current-state implementation and creates no SQL schema or migration authority.

## Generic declared-capability guard

The pre-existing generic invariant remains independently proven:

```text
provider declares CurrentStateAuthorityReading
provider returns null CurrentStateAuthorityCutProvider
    -> capability validation succeeds
    -> persistence finalization succeeds
    -> ICurrentStateAuthorityCutProvider resolution fails
```

This remains distinct from the unsupported-provider path, which fails during selected-provider capability validation before provider construction.
