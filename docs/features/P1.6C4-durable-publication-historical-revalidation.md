## Decision and identities

V2 publishes an immutable proof bundle, immutable result and exact batch manifest atomically with its checkpoint and read index. Independently reconstruct C1 authority, C2 operands and C3 evaluation inside the publication authority; never trust a caller's success label or detached preflight.
Use the reserved V2 processor/definition/policy and evidence identities from C3 unchanged.
Reserve publication family `planned-production-availability-publication/v2` with its own format discriminator. Do not feed these bytes to existing V1 containment result codecs/publisher or reinterpret their numeric format fields.
An encoding version is separate from semantic policy/definition, proof content identity, processor identity and coverage assessment revision.

## Logical persisted records

| Proposed record | Logical key and retained content |
| --- | --- |
| HistoricalAuthorityReceipt | Typed authority kind + immutable identity/revision; canonical schedule selection/empty decision, producer membership, activity/continuity or exact coverage payload and its dependencies |
| AvailabilityProofBundle | Content identity; full C1 subject/cut/policies; complete reference inventory; C2 fragments, exact ticks, admission states and diagnostics |
| AvailabilityInvariantWitness | Content identity; typed conflict/invariant, exact source references, competing fragments/values and bound cut; not a fabricated legacy outside-running witness |
| AvailabilityResult | Slot=(V2 processor, full evaluation key, exact aggregation revision, semantic policy); canonical C3 status/reason/value and proof/witness references |
| AvailabilityPublicationManifest | Slot=(V2 processor, exact source revision); complete sorted result-slot/content-ID set and batch kind |
| AvailabilityPublicationCheckpoint | Exact V2 processor/source binding; latest accepted source revision and manifest identity |
| AvailabilityReadIndex | Full evaluation key + V2 processor -> exact retained result identity; derived mutable index, never independent truth |

Logical keys must compare complete canonical identities, not only hashes or abbreviated GUID/date labels. Digest matches require byte equality checks; collisions/conflicting content fail closed.
Immutable records cannot be updated in place. Checkpoint/index changes cannot rewrite old result slots. No foreign processor may share a checkpoint.
C4 implementation must choose physical SQL names, indexes/FKs and a repository migration under separate review. Proposed records are not permission to create tables now.

## Proof representation and missing-authority receipts

Proof bundle contains the exact C1 receipt inventory, C2 canonical provenance, integer UTC ticks, original typed position domains, schedule/exclusion content and expansion rules, completion/continuity evidence, exact coverage subject AND revision, and result-specific omissions.
Persist reference payloads in the immutable authority archive or reference an immutable durable store with enforced retention and exact reads. An opaque reference without resolvable payload cannot support a numeric result.
Retain a closed dependency inventory with content identities; transitive references are checked for ownership, version, cycles and completeness. Bound resource limits must reject oversized/deep/cyclic proofs, not truncate them.

InsufficientEvidence results require an immutable capture of the historical selection domain and the exact missing/unproven authority decision, verified in the publication transaction. A bare empty query is not a proof of approved no-production.
Distinguish:
- **Historically absent/not established authority:** verified selection at the cut supports an honest insufficient result and explicit omission inventory.
- **Referenced payload lost or contradictory:** historical integrity failure; cannot be converted into a new missing-evidence result.
- **Authority added after the bound cut:** cannot change the original result. Later recovery/admission requires separately versioned authority/policy review; it is not same-slot replay.

For NoPlannedProduction retain positive, complete historical no-production selection authority; unknown activity remains absent and cannot be archived as zero total.
For Calculated zero retain complete planned non-running reconciliation, not merely an empty running list.
C1-R1/R2/R3 are prerequisites to implementing these receipts, not solved merely by this storage vocabulary.

## Canonical encoding requirements

Define a new tagged, length-prefixed binary envelope: family discriminator, encoding version, semantic identities, typed payload and complete dependency IDs. Fixed-width numbers have one specified endianness; all lengths/counts are bounded before allocation.
Use explicit presence tags to distinguish absent, unknown and established-empty sets. Strings use one strict lossless ordinal encoding with no normalization/case folding; malformed input is rejected. C2 canonical ordering is mandatory and duplicate keys are rejected.
Persist ticks as signed 64-bit integers with checked duration sums. Positions use their existing full unsigned domain and distinct type tags. Store decimal ratio as the four exact .NET decimal bit fields with a canonical scale/sign representation; preserve original numerator/denominator tick totals independently.
Canonical decimal normalization removes trailing base-10 scale zeros and maps all zeros to positive scale-zero; decoding rejects alternate encodings. Recompute the decimal result with the bound C3 algorithm and compare canonical numeric content.
Reserve SHA-256 content IDs with distinct domain tags for authority, proof, witness, result and manifest. Hash the family/version and canonical payload, not platform GetHashCode or JSON text. Complete bytes remain authoritative on a digest collision.
Before codec freeze require independent encoder/decoder vectors covering Unicode, null/empty, full position range, sub-second ticks, repeating decimals, malformed lengths, unsupported tags and collision behavior. Exact tag numbers/SQL DDL remain implementation specifications for review.

## Publication transaction and lock order

1. Validate bounded caller input and freeze buffers. This is structural preflight only.
2. Begin caller-owned Serializable transaction. Acquire the exclusive per-V2-processor publication gate; validate/register exact immutable processor/source/policy/format binding.
3. Lock checkpoint, exact revision manifest slots and read-index logical key ranges in deterministic ordinal order. Reject backward cuts and expected-predecessor mismatch. Validate retained state before mutation.
4. Read exact aggregation revision and historical contribution membership. Resolve pinned authority receipts and their complete dependencies. Lock authority selection/membership ranges needed to prove absence and completeness, not only rows returned by a query.
5. Independently run C1 verification, C2 construction and C3 evaluation using those historical inputs. Compare full canonical caller proposal to independently reconstructed results and complete manifest. Reject mixed cuts or policy/version substitution.
6. Lock incoming immutable archive slots in typed/content-ID order; validate exact replay/content conflicts. Insert authority/proof/witness/result records and their complete dependency links.
7. Publish complete batch manifest, read-index updates and checkpoint in the same transaction. Revalidate exact retained identities and inventory; commit once.
8. Any failure rolls back the complete transaction. Cancellation/connection loss does not establish rollback; retry uses the identical immutable proposal and expected predecessor.

One repository-wide lock-order design must cover these steps and shared authority writers before implementation. Order is gate -> registration/checkpoint/index ranges -> historical source/authority ranges -> archive slots -> DML/checkpoint. Existing source writers and V1 writers may lock differently; explicit deadlock/interleaving tests are mandatory. This proposal does not assert compatibility has already been proved.
No production migration, scheduled task or schema repair is performed by publication. External historical stores must provide pinned immutable receipts verified before admission; mutable remote reads cannot participate as trusted evidence.

## Replay and concurrency

Identical slot and canonical bytes replay idempotently, including retry after uncertain commit. A conflicting result/proof/manifest for the same slot is rejected.
Checkpoint replay requires the complete exact batch key/content set; it cannot repair a missing result, witness, dependency, read index or manifest.
Historical read replay remains possible for an older archived slot without moving a newer checkpoint backwards; publication retries against a superseded expected predecessor return a typed predecessor conflict unless an independently verified already-committed receipt proves identical prior completion.
Concurrent identical writers converge on one immutable publication; different bytes at the same slot conflict. Shared proof/witness insertion requires byte equality and complete dependency links, never last-writer-wins.
New source revisions cannot fill gaps at an older cut. Same-cut current configuration changes cannot alter the historical receipt.
A retained partial/corrupt state fails integrity validation; automatic repair is outside scope.

## Reader contract and retention

Exact read specifies V2 processor, full key and result source revision (or resolves the V2 index once to a pinned exact target). Never fall back to another processor/policy or use current schedule/coverage heads.
Read the committed manifest/result/proof/dependencies under a coherent transaction and independently validate canonical identities, completeness and C1-C3 reconstruction at that exact historical target. A cache may store only validated immutable content; mutable index selection must remain pinned per read.
Expose distinct Found, Absent, UnsupportedEncoding, Unavailable and Corrupt read outcomes; they must not be confused with C3 metric Unavailable/InsufficientEvidence. Transient infrastructure errors/cancellation propagate.
Found includes exact semantic/encoding IDs, source cut, complete provenance and metric result. Unsupported readers fail closed; no silent downgrade to a V1-shaped result. HTTP/dashboard projection requires separately reviewed additive/versioned transport support.
Retain all transitive proof authority for every retained result. FK/reference checks must prevent deleting referenced proof/witness/authority content. Retention/archival cannot keep a numeric result while discarding the evidence required to reproduce it.
No automatic dashboard source switch, default processor change or V2 OEE dependency combination.
