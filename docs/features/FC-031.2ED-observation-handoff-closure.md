## Closed scope

FC-031.2E.D establishes one graph-scoped mapping/state authority ownership decision for Edge observation composition.

The Edge observation graph now consumes the persistence provider's mapping-coverage and machine-state/activity authority stores when the provider supplies both roles as one complete pair. When neither provider role exists, Edge creates one deterministic in-memory fallback pair. A provider that supplies only one role is rejected explicitly.

All Edge authority interfaces, compatible concrete aliases, and observation consumers derive from that selected pair. No consumer independently selects or manufactures an authority store.

## Ownership authority

Provider ownership is determined only from resolved `PersistenceProviderServices` authority roles:

```text
provider mapping role present
+ provider state/activity role present
    -> select exact provider-owned pair

provider mapping role absent
+ provider state/activity role absent
    -> select one Edge-owned fallback pair

exactly one provider role present
    -> fail explicitly
```

DI descriptor presence, provider name, and concrete implementation type do not determine ownership.

The graph-scoped holder does not resolve `IMappingCoverageAuthorityStore` or `IMachineStateActivityAuthorityStore` while choosing ownership, avoiding recursive or independently ordered authority selection.

## Selected-graph projection

The selected pair is projected consistently through Edge observation composition:

```text
selected mapping store
    -> IMappingCoverageAuthorityStore
    -> MachineSignalMappingProcessor

selected state/activity store
    -> IMachineStateActivityAuthorityStore
    -> IMachineStateActivityCursorReader
    -> JointAuthorityMachineStateActivityProcessor
```

The durable observation pipeline therefore publishes mapping and state/activity authority into the same selected graph exposed through the Edge authority interfaces.

## Concrete compatibility aliases

Concrete compatibility services are projections of the already-selected authority objects; they do not participate in ownership selection.

When the selected mapping authority is `InMemoryMappingCoverageAuthorityStore`, the concrete mapping service aliases that exact selected object. When the selected state/activity authority is `InMemoryMachineStateActivityAuthorityStore`, the concrete state/activity service aliases that exact selected object.

If a future selected authority implementation is not compatible with one of those concrete services, concrete compatibility resolution fails explicitly rather than manufacturing an unrelated in-memory store.

This preserves the existing concrete state/activity production compatibility seam and the concrete mapping composition/test compatibility seam without promoting either concrete type to provider-neutral ownership authority.

## Finalized InMemory provider proof

With finalized InMemory persistence and `CurrentStateAuthorityReading` explicitly requested:

```text
PersistenceProviderServices.MappingCoverageAuthorityStore
    === IMappingCoverageAuthorityStore
    === compatible InMemoryMappingCoverageAuthorityStore

PersistenceProviderServices.MachineStateActivityAuthorityStore
    === IMachineStateActivityAuthorityStore
    === compatible InMemoryMachineStateActivityAuthorityStore
```

Observation processing publishes through those selected provider-owned stores.

The activated `ICurrentStateAuthorityCutProvider` is the exact provider-owned cut provider exposed by persistence finalization. After an observation-processing cycle, its stable authority cut observes acquisition, mapping, and evaluation authority from the same provider-owned graph.

This closes the previously possible split between provider-owned current-state reading and independently Edge-created mapping/state authority stores.

## SQL fallback compatibility proof

The SQL persistence provider does not supply mapping-coverage or machine-state/activity authority roles through `PersistenceProviderServices`.

Edge observation composition therefore selects one deterministic fallback pair:

```text
IMappingCoverageAuthorityStore
    === InMemoryMappingCoverageAuthorityStore fallback

IMachineStateActivityAuthorityStore
    === InMemoryMachineStateActivityAuthorityStore fallback
```

No SQL current-state authority capability, SQL schema, SQL migration, or SQL provider implementation is introduced by this slice.

The activated cut-provider read is intentionally not a SQL obligation for FC-031.2E.D.

## Standalone Edge compatibility proof

When Edge observation composition is registered without finalized `PersistenceProviderServices`, the same deterministic authority-store fallback remains available and its compatible concrete aliases resolve to the exact selected objects.

Standalone registration does not create `IObservationIngestionStore`; a complete executable observation pipeline still requires that ingestion dependency to be supplied externally. FC-031.2E.D does not change that existing boundary.

## Competing-registration proof

Pre-existing mapping/state authority registrations cannot displace the holder-selected Edge fallback pair.

The Edge observation graph exposes the pair selected by its graph-scoped ownership decision, and compatible concrete aliases resolve to those exact selected objects rather than to competing registrations.

## Mixed-role failure proof

A `PersistenceProviderServices` graph that supplies exactly one of the two authority roles is invalid for Edge observation composition.

Both public Edge authority resolution paths fail explicitly:

```text
resolve IMappingCoverageAuthorityStore
    -> explicit mixed-role failure

resolve IMachineStateActivityAuthorityStore
    -> explicit mixed-role failure
```

No fallback half is exposed from a mixed provider graph.
