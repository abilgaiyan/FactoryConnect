# 1. Primitive canonical encodings

Unless a field explicitly states otherwise, every multi-byte integer is encoded **big-endian**.

```text
UInt8       1 byte
UInt16      2 bytes, unsigned big-endian
UInt32      4 bytes, unsigned big-endian
UInt64      8 bytes, unsigned big-endian
Int32       4 bytes, two's-complement big-endian
Int64       8 bytes, two's-complement big-endian
Boolean     one byte: 0x00 false, 0x01 true; all other values invalid
```

## 1.1 CanonicalStringV1

Physical encoding:

```text
UInt32 byteLength
byteLength exact strict-UTF-8 bytes
```

The primitive string codec freezes these rules:

```text
strict UTF-16 input validity          required
.NET string.Length                    <= 256 UTF-16 code units
strict UTF-8 payload                  required
UTF-8 payload length                  <= 768 bytes
Unicode normalization                 none
case normalization                    none
whitespace normalization              none
BOM/U+FEFF stripping                  none
control/NUL stripping                 none
empty primitive string                allowed
```

Both size limits are independent and MUST be checked.

Encoder order:

1. validate the input as well-formed UTF-16;
2. reject an unpaired high or low surrogate;
3. require `.NET string.Length <= 256`;
4. encode using strict UTF-8 with replacement fallback disabled;
5. require UTF-8 byte length `<= 768`;
6. write the UInt32 big-endian byte length;
7. write the exact UTF-8 payload.

Decoder order:

1. read UInt32 big-endian byte length;
2. reject a declared length `> 768` before allocation/read;
3. require exactly the declared bytes;
4. decode using strict UTF-8 with replacement fallback disabled;
5. require decoded `.NET string.Length <= 256`;
6. apply the containing field's required/optional and empty/non-empty domain rule.

Invalid UTF-8 includes overlong forms, UTF-8 encodings of surrogate code points, invalid continuation sequences, and scalar values above U+10FFFF.

No normalization is performed. Therefore, for example:

```text
"é"                 != "e\u0301"
"A"                 != "a"
"abc"               != " abc"
"abc"               != "abc "
"\uFEFFabc"         != "abc"
```

U+FEFF has no codec-level BOM semantics. If present in a string, including at the beginning, it is ordinary identity data and is encoded as its exact UTF-8 scalar bytes.

U+0000, TAB, LF, CR, and other valid Unicode scalar values are not stripped or rejected by the primitive codec. A field/domain contract may impose a narrower rule.

The primitive permits an empty string (`byteLength = 0`). Required identity fields and fields explicitly described as non-empty reject it at the field/domain layer.

Permanent boundary vectors include:

```text
256 ASCII code units                 ACCEPT
257 ASCII code units                 REJECT UTF-16 LIMIT
256 × U+00E9                         ACCEPT (256 UTF-16 / 512 UTF-8)
128 × U+1F600                        ACCEPT (256 UTF-16 / 512 UTF-8)
129 × U+1F600                        REJECT UTF-16 LIMIT
256 × U+0800                         ACCEPT (256 UTF-16 / 768 UTF-8)
UTF-8 payload > 768 bytes            REJECT
unpaired surrogate                   REJECT
invalid/overlong UTF-8               REJECT
```

## 1.2 Optional values

Canonical optional encoding is:

```text
0x00                    absent
0x01 + encoded value    present
```

Any other tag is invalid. A present string remains subject to the containing field's non-empty rule.

## 1.3 Guid V1 bytes

A Guid is exactly 16 bytes in big-endian field order:

```text
UInt32 A
UInt16 B
UInt16 C
8 remaining bytes unchanged and in Guid field order
```

Known vector:

```text
Guid  00112233-4455-6677-8899-aabbccddeeff
V1    00 11 22 33 44 55 66 77 88 99 AA BB CC DD EE FF
```

On the target .NET runtime, `guid.TryWriteBytes(destination, bigEndian: true, out _)` is the preferred implementation. Any alternative implementation MUST produce exactly the same bytes.

## 1.4 DateOnly

```text
Int32 DayNumber
```

`DayNumber` is the exact .NET `DateOnly.DayNumber` value.

## 1.5 UTC DateTimeOffset

Only offset-zero timestamps are valid.

```text
Int64 utcTicks
```

`utcTicks` is the UTC `DateTime` tick value represented by the `DateTimeOffset`. A value whose offset is not `+00:00` is rejected before encoding and when reconstructing persisted state.

## 1.6 UInt64 positions/revisions

Positions and revisions are encoded as UInt64 big-endian. SQL may persist the same logical value as `decimal(20,0)` where required by the existing physical contract.

## 1.7 CanonicalDecimalTextV1

Operational metric/component decimal values are encoded as **CanonicalDecimalTextV1**, then as CanonicalStringV1.

Normative authority is exact decimal structure and integer arithmetic only.

The following are explicitly **not** normative authorities:

```text
decimal.ToString
decimal.Parse / decimal.TryParse
G29
culture-sensitive formatting
runtime-dependent rounding behavior
```

A CLR decimal is interpreted conceptually as:

```text
sign
96-bit unsigned coefficient C
scale S in [0, 28]
value = (-1)^sign × C × 10^-S
```

### Normalization

```text
if C == 0:
    sign = positive
    S = 0
otherwise:
    while S > 0 AND C mod 10 == 0:
        C /= 10
        S -= 1
```

Therefore every signed/scaled zero encodes as `"0"`, and `1m`, `1.0m`, and `1.00m` all encode as `"1"`.

For nonzero normalized values:

```text
D = decimal digits of normalized C, with no leading zeros
E = D.Length - S - 1
```

Notation selection is frozen:

```text
E >= -4     FIXED
E <= -5     SCIENTIFIC
```

CLR decimal's maximum positive exponent is +28, so V1 has no positive-scientific branch.

### Fixed form

```text
If S == 0:
    D
Else:
    P = D.Length - S
    If P > 0:
        D[0..P] + "." + D[P..]
    Else:
        "0." + repeat("0", -P) + D
```

Prefix `-` only for a normalized nonzero negative value.

### Scientific form

```text
[optional "-"]
first digit of D
["." + remaining digits of D, if D.Length > 1]
"E-"
two-digit absolute E
```

Scientific V1 therefore uses only exponents `-05` through `-28`, uppercase `E`, mandatory negative exponent sign, and exactly two exponent digits.

Examples:

```text
0.0001          -> "0.0001"
0.00001         -> "1E-05"
0.000012345     -> "1.2345E-05"
1E-28           -> "1E-28"
-1E-28          -> "-1E-28"
```

### Exact decoder

The decoder MUST:

1. validate the V1 ASCII lexical grammar;
2. parse sign exactly;
3. parse coefficient digits using arbitrary-precision integer arithmetic;
4. parse decimal-point position exactly;
5. parse the exponent exactly when present;
6. convert to exact signed integer coefficient × 10^power;
7. normalize mathematically;
8. prove exact CLR decimal representability: normalized scale `<= 28`, coefficient fits 96 bits, and no nonzero digit is discarded;
9. construct the decimal exactly without rounding;
10. canonically re-encode using CanonicalDecimalTextV1;
11. require ordinal equality between original text and canonical re-encoding;
12. otherwise reject.

Frozen rejection semantics are:

```text
InvalidSyntax
MagnitudeOverflow
ScaleOverflow
RoundingRequired
Underflow
NonCanonicalRepresentation
```

Examples:

```text
"1E-29"       -> reject: exact scale cannot fit
"10E-29"      -> exact value is representable, but canonical form is "1E-28"; reject noncanonical
"0.00001"     -> exact value is representable, but canonical form is "1E-05"; reject noncanonical
"1E-04"       -> exact value is representable, but canonical form is "0.0001"; reject noncanonical
```

Permanent identity/boundary coverage includes zero variants, trailing-zero equivalents, the `-4/-5` notation boundary, minimum positive/negative decimal, `decimal.MaxValue`, `decimal.MinValue`, high-precision exact values, noncanonical spellings, overflow, underflow, and rounding-required inputs.

# 2. MachineOrderKey V1

`MachineOrderKey` is permanently V1.

```text
MachineOrderKeyV1 = Guid V1 bytes from section 1.3
```

Lexicographic SQL `binary(16)` comparison therefore matches `.NET Guid.CompareTo` field order.

Migration 005 shall define it as a deterministic persisted computed column from `MachineId`:

```sql
MachineOrderKey AS
    CONVERT(
        binary(16),
        REPLACE(CONVERT(char(36), MachineId), '-', ''),
        2)
    PERSISTED
```

It MUST NOT be an independently trusted writer-supplied value.

If the supported SQL Server target cannot persist/index this exact semantic expression, implementation MUST stop for architecture review rather than silently trusting writer bytes.

Independent .NET characterization passed the known vector, boundary vectors, and 10,000 randomized Guid pairs. SQL conformance remains an implementation proof once migration 005 exists.

## 3.3 Decoder and row mutual validation

A V1 decoder requires exact magic/type/version, strict primitive decoding, valid domain identities, valid period shape, and complete input consumption. Unknown versions and trailing bytes are deterministic failures.

Before a projection row may participate in reporting, projection reads, replay validation, or checkpoint-manifest equality, the SQL provider validates:

```text
SHA-256(EvaluationKeyBinary) == EvaluationKeyHash
embedded codec version == EvaluationKeyCodecVersion == 1
decoded MachineId == structured MachineId
decoded MachineId GuidV1 bytes == computed MachineOrderKey
decoded period == structured period columns exactly
decoded context == structured presence/value columns exactly
decoded MetricKey == structured MetricKey
decoded DefinitionVersion == structured DefinitionVersion
```

Mismatch is persisted-data corruption, never “row missing”.

For reporting, every projection row belonging to the selected projection processor identities is integrity-validated before date/context/status/seek filters determine the returned page.

## 4.4 Component evidence V1

```text
1. OperandName                 canonical non-empty string
2. SourceMachineId             Guid V1 bytes
3. SourcePeriod                canonical period identity
4. ComponentKey                canonical non-empty string
```

## 4.5 Dependency evidence V1

Each dependency evidence item is:

```text
1. OperandName
   canonical non-empty string
2. DependencyDefinitionId
   metric definition identity
3. NestedProjectionSnapshot
   canonical blob containing one complete FCDS V1 snapshot
```

Nested bytes include their own FCDS magic/type/version. No nested hash is inserted into the parent payload.

## 4.6 Recursive coherence

For every component evidence item:

```text
SourceMachineId == containing projection EvaluationKey.MachineId
SourcePeriod == containing projection EvaluationKey.Period
SourceRevision == containing projection SourceRevision
SourceRevision.MetricInputStreamId.MachineId == SourceMachineId
```

For every dependency evidence item, the nested projection MUST match the parent in:

```text
ProjectionProcessorId
SourceRevision
MachineId
Period
ProductionOrderId
OperationId
PartId
OperatorId
```

Only the metric definition may differ.

Additionally:

```text
DependencyDefinitionId == nested EvaluationKey.DefinitionId
```

A mismatch at any recursive boundary is corruption.

## 4.7 Collection semantics

Component and dependency collections preserve exact provider-neutral list order. The codec performs no sorting.

`OperandName` must be unique across both collections within each projection snapshot. Duplicate component, duplicate dependency, and cross-kind duplicate operands are rejected.

## 4.8 V1 resource limits

Frozen limits:

```text
complete FCDS binary, including 7-byte envelope    1 .. 16,777,216 bytes
maximum recursive projection depth                 64
maximum component items per projection             65,535
maximum dependency items per projection            65,535
maximum TotalEvidenceNodeCount                     262,144
```

Depth counts the root as `1`. Depth `64` is accepted when otherwise valid; descent to depth `65` is rejected.

`TotalEvidenceNodeCount` counts every component-evidence node and dependency-evidence node across the complete recursive tree. It excludes root and nested projection objects themselves.

All size/count arithmetic is checked. Provably excessive encoded lengths/counts are rejected before allocation or iteration where possible.

## 4.9 Complete-input consumption

A successful decoder position MUST equal the exact end of every bounded blob independently:

```text
root FCDS
embedded FCEK
nested FCDS at every depth
```

Any trailing byte, including zero padding, is rejected.

# 5. Version evolution policy

V1 is immutable.

```text
writer
  emits exactly one configured current version

reader
  continues to read every released version that can remain in durable storage

unknown version
  rejected deterministically

existing V1 bytes
  never reinterpreted under newer rules

hash
  covers magic + type marker + embedded codec version + complete payload

SQL version column
  equals the embedded version
```

A future V2 requires a separately reviewed compatibility/migration decision. V2 does not silently extend V1 enum domains, nested FCEK support, resource limits, decimal spelling, or string identity semantics.

# 6. Validation order

## 6.1 Evaluation key row

```text
1. physical binary length/nonempty checks
2. SHA-256 recomputation and EvaluationKeyHash equality
3. magic + type marker
4. embedded version known and equals SQL EvaluationKeyCodecVersion
5. strict V1 decode with bounds/domain checks
6. complete-input consumption
7. decoded key versus structured projection columns
8. decoded MachineId versus computed MachineOrderKey
9. only then may the row enter filtering/order/seek/reconstruction
```

## 6.2 Dependency evidence row

```text
1. physical shape + complete payload size bound
2. SHA-256 recomputation and DependencySnapshotHash equality
3. magic + type marker
4. embedded version known and equals DependencySnapshotCodecVersion
5. strict recursive V1 decode with all resource/domain/coherence bounds
6. complete-input consumption at every nesting level
7. provider-neutral projection invariants and duplicate-operand checks
8. structured dependency header versus decoded definition
9. only then reconstruct provider-neutral dependency evidence
```

Hash failure is reported before parsing untrusted payload structure.

# 7. Deterministic corruption behavior

Malformed persisted state fails the current provider operation before returning a partial page, partial projection, replay success, or checkpoint equality result.

Codec/integrity failures surface as `InvalidDataException` or a provider-internal subtype with deterministic artifact/row context. They are never normalized into:

```text
missing projection
empty evidence
continuation exhausted
filter mismatch
checkpoint conflict
```

No reader repairs, rewrites, rounds, normalizes, trims, or otherwise canonicalizes corrupt durable bytes during reconstruction.
